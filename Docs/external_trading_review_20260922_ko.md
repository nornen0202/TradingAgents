# 외부 투자 프로젝트 조사와 실행 개선 — 2026-09-22

## 판단

현재 우선순위는 전략 수를 늘리는 것보다 **원래 주문과 실제 체결의 일치, 손실 상황에서의 위험 축소, 재현 가능한 성과 검증**이다. 외부 프로젝트 9개의 공식 문서·저장소를 비교해 필요한 설계를 현재 코드에 적용했다. 외부 엔진이나 에이전트를 설치했다고 수익이 개선되는 것으로 보지 않는다.

이번 범위는 공개 문서·관련 API 및 현재 코드의 동작 검토다. 모든 외부 엔진을 설치하거나 전체 코드를 감사하지는 않았다. 프로젝트의 예시 수익률·인기·별점으로 전략을 선정하지 않았다. 사용자 운용 기준은 기존 계좌 기반 모의매매이며 실제 주문 전송은 없다.

외부 소스 코드를 복사하거나 신규 엔진 의존성을 추가하지 않고 설계 원칙을 자체 구현했다. 향후 코드를 직접 도입한다면 해당 버전의 라이선스와 의존성을 별도로 확인해야 한다.

추세 전략의 장기 연구 근거는 있지만, [AQR의 장기 추세 연구](https://www.aqr.com/Insights/Research/Journal-Article/A-Century-of-Evidence-on-Trend-Following-Investing)는 다양한 선물·통화 등을 포함한 연구다. 이를 한국 개별주 현금계좌의 현재 수익 보장이나 본 프로젝트의 성과로 옮겨 해석하지 않는다.

## 발견한 문제와 구현한 보완

1. **체결 조회가 원래 주문과 다른 경우:** 이전에는 주문번호와 수량의 내부 정합성을 주로 확인했다. 이제 계좌정보를 제외한 원래 요청을 저장하고 종목·매수/매도·수량·지정가가 모두 맞아야 대사를 통과한다. 과거 원장에 원본 조건이 없으면 추측해서 복원하지 않고 확인 필요 상태로 둔다.
2. **체결 결과의 역행·누락:** 누적 체결 수량이 줄거나 체결 완료 주문이 미체결로 되돌아가면 신규 주문을 차단한다. 조회 누락·중복·실패도 대사 문제로 보존한다. 후속 조회가 정합성을 회복하면 해당 문제를 해제한다. 주문번호가 없는 UNKNOWN은 자동으로 다른 주문과 연결하지 않는다.
3. **오류가 취소까지 막는 문제:** 다른 신규 주문이 UNKNOWN이어도 이미 확인된 주문의 잔량 취소는 가능하게 했다. 동일 취소 요청은 저장된 접수 결과를 반환하며 취소 접수를 완료로 간주하지 않는다.
4. **손실 제한이 위험 축소까지 막는 문제:** 로컬 모의 원장의 일일 손실 제한은 기본적으로 신규 매수를 막고 확인된 보유분 매도만 허용한다. 수량·일일 회전·시세 등 기존 한도는 남는다. 수동 긴급 중단은 매도까지 정지한다. `daily_loss_reduce_only=false`로 기존 전체 중단 정책을 별도 실험에 유지할 수 있다.
5. **호출 속도와 만료:** 같은 프로세스·앱키의 요청을 기본 1.1초 간격으로 제한하고, 인증·대기 후 전송 직전 만료를 다시 검사한다. 프로세스 간 호출량 통합은 아직 없으므로 같은 키를 여러 실행기로 동시에 운용하지 않는다. 로컬 원장의 만료시각 경계도 바로 만료되도록 수정했다.
6. **등록 부담과 비밀정보:** 모의투자용 App Key, App Secret, 전체 계좌번호 10자리의 세 항목을 받는 Windows 화면을 추가했다. [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)로 현재 사용자용 암호화 저장 후 인증·잔고·당일 주문 조회만 점검한다. JSON 편집, 환경변수 설정, 상품코드 분리와 명령 입력을 사용자가 할 필요가 없다.

새 원장에는 변경된 한도를 기록한다. 기존 원장과 한도가 다르면 새 실험 원장을 사용하며 과거 성과를 이어 붙이지 않는다. 등록 도구의 암호화 묶음이 기존 환경변수/JSON의 모의 설정보다 우선하며, 암호화 파일이 손상되면 다른 키로 몰래 대체하지 않는다. Windows 사용자나 실행 PC가 바뀌면 재등록이 필요하다.

로컬 검증에서는 전체 1,133개 테스트와 78개 하위 테스트가 통과했고 1개가 건너뛰어졌다. Windows 암호화 저장·복호화·손상 파일 거부, 등록 후 조회 전용 점검, 대사 불일치·중복·역행·취소 재전송 차단을 확인했다. 등록 창의 생성·입력 가림·화면 내 배치, 모바일 360/390/430px 화면, 정적 검사도 통과했다. 실제 VTS 인증·체결은 접속정보가 없어 검증하지 못했다.

## 성과 검증: 검사 통과와 수익 우위는 별개

이전 감사에서 로컬에 생성한 Yahoo Finance 수정주가 캐시를 재사용했다. 6개 고정 가설 × 3개 연도 × 편도 10/30/100bp 비용으로 54회 평가했다. 2026년은 9월 18일까지다. 각 연도는 별도 초기 현금에서 출발하므로 표의 수익률을 연속 운용 성과처럼 복리 연결하면 안 된다.

아래는 **편도 30bp 가정의 연구 시뮬레이션 수익률**이다. 실제 계좌 수익률이나 현재 시장 데이터의 독립 검증 결과가 아니다.

| 전략 | 2024 | 2025 | 2026~9/18 |
|---|---:|---:|---:|
| SPY 보유 | 25.27% | 16.66% | 11.58% |
| SPY 200일 추세 | 25.19% | 9.98% | 0.59% |
| 미국 분산 126일 모멘텀 | 25.89% | 29.35% | -3.67% |
| KOSPI200 ETF 보유 | -9.15% | 94.16% | 79.98% |
| KOSPI200 ETF 200일 추세 | -3.84% | 69.13% | 79.87% |
| 국내 ETF 126일 모멘텀 | -16.75% | 44.22% | 43.78% |

미국 분산 모멘텀의 우위는 해마다 유지되지 않았다. 국내 추세 필터도 2026년 구간 최대 낙폭이 -40.58%로, 보유 기준선 -40.76%와 큰 차이가 없었다. 월간 조정과 단순 200일 필터만으로 급격한 손실을 해결했다고 볼 수 없다. 매매 빈도를 늘리거나 이전의 수익률 1위 전략을 그대로 채택하는 결론은 지지되지 않는다.

신호의 과거 구간 일치 검사 72건과 계산 초기 구간 검사 18건은 모두 통과했다. 다만 이는 검사한 시점·함수에 관한 결과다. 현재 상장 종목만 고르는 편향, 나중에 수정된 주가, 당시 정보 공개 시점, 거래 가능성은 별도 문제다. 수정주가의 소수 단위를 거래하는 연구이므로 실제 정수 주식, 세금, 구독료, 환율, 체결 대기, 현금 이자는 반영되지 않았다. 특히 큰 국내 수익·낙폭 수치는 독립 데이터 대조 전 운용 근거로 승격하지 않는다.

재현 명령:

```powershell
$env:PYTHONPATH='.'
python tools/validate_strategy_research.py --prices <로컬에서-생성한-etf_prices.pkl> --output .runtime/research-validation.json
```

외부에서 받은 피클 파일은 사용하지 않는다. 출력에는 가격 파일 SHA-256, 각 검사 결과, 54개 시나리오의 수익·낙폭·비용·노출·주문 수가 포함된다.

## 사용자가 남겨야 할 작업과 다음 검증

[모의투자 간편 등록 안내](kis_demo_quickstart_ko.md)에 공식 신청 링크와 세 항목 입력 절차를 정리했다. 본인인증, 이용약관 확인·동의, 모의계좌/API 신청 완료는 사용자가 수행한다. 등록 도구가 이후 저장과 조회 점검을 처리한다.

전용 접속정보가 없으면 VTS 실증을 완료했다고 표시하지 않는다. 등록 이후에는 모의계좌의 실제 잔고·매수가능액과 기존 계좌 복제 원장의 차이부터 대사해야 한다. 제한된 모의 주문·체결·잔량 취소, 비용을 포함한 미래 성과 비교, 동일 자료의 독립 엔진 재검증이 남아 있다. 해외 주문·환율 연결과 상시 자동 주문 실행은 아직 활성화하지 않았다.
