# 11월 16일 미국 보고서의 입력 검증과 보호 기준

## 확인된 사실과 원인

[대상 보고서](https://nornen0202.github.io/TradingAgents/work/v1/us/report/events/9fd8352f2a578156e738f31554737c65a65bb0ea31b0844a8e30524b96195c00.html)는 2026-11-16 23:13:42 KST(09:13:42 EST)에 게시됐다. 원본은 `20261116T175030_local-scheduler-us-full`이다. 30종목 처리는 완료됐지만 시세는 11월 13일 15:55 EST부터 11월 16일 06:40 EST까지, 계좌는 11월 16일 21:08 KST였다. 게시 시각은 이 관측들을 갱신하지 않는다.

게시 시각은 미국 정규장 개장 전이다. 11월 13일은 직전 완료 거래일이므로 일봉 날짜 자체를 11월 16일로 바꾸는 것은 해결책이 아니다. 날짜만 있는 일봉 기준과 검증된 관측 시각도 구별해야 한다. 원래 보고서는 조건부 투자 계획이고 이미 실행 불가로 표시돼 있었으며, 이 조사에서 해당 보고서로 주문이 실행됐다는 증거는 발견하지 않았다.

원본 도구 요청 영수증을 기존 검증기로 다시 검사하면 **30/30종목 모두 필수 연구 자료 부족**이다. 회사 뉴스는 전 종목에서 누락됐고, 추가로 재무상태표 2종목, 현금흐름표 3종목, 손익계산서 2종목, 공시 1종목에 누락이 있었다. 원본 AAPL 요청에는 Alpha Vantage 요금제/호출 제한과 Yahoo의 사용 가능한 결과 부재가 기록돼 있다. 생산 성공과 자료 충족은 별개의 상태다. 시세만 새로 받거나 검토일을 늘려도 이 연구 자료가 채워지지 않는다.

코드에서 확인한 재발 경로는 다음과 같다.

1. `source_freshness_receipt`가 원본 연구의 가격 시점 대신 최신 실행 행의 시세로 연구 시점 적합성을 계산했다. 시세 갱신이 과거 연구 검증 상태를 바꿀 수 있었다.
2. 원본 파일·결정 해시와 연결된 연구 검증은 선택형 보고서 컨텍스트에서만 수행됐다. 기본 투자 계획은 원분석 작성 시각과 조건만으로 `CONDITIONAL_PLAN`이 될 수 있었다.
3. KIS 미체결 조회 실패를 빈 목록으로 바꾸면서 잔고가 정상이면 계좌 전체를 `VALID`로 남겼다. 미체결 0건과 조회 실패가 검증 단계에서 구별되지 않았다.
4. 기존의 더 엄격한 보호 기준 유지와 미체결·기체결 대조가 모든 투자 계획에 강제되는 공통 조건은 아니었다. 일부 원분석의 설명에 의존했다.

## 변경

- 연구 가격 시점은 원본 종목의 실행 계약에 연결된 관측 시각과 원분석 완료 시각으로 검사한다. 누락·중복·불일치·날짜만 있는 값·미래 시각은 미검증으로 남긴다. 실행 overlay 시각은 이 검증을 회복시키지 않는다.
- 기본 보고서에도 기존 원본 파일/해시 검증기를 적용한다. 도구 자료 수신 검증과 종목 커버리지를 따로 표시하며, 검증되지 않은 계획은 원래 방향을 보존하고 `REVIEW_REQUIRED`로 표시한다. 이 검증은 모든 재무 내용의 정확성이나 완전한 과거 시점 적합성을 보증하지 않는다.
- 미체결 조회 실패 시 잔고는 참고용으로 보존하지만 계좌 상태는 `INVALID_SNAPSHOT`, 미체결 상태는 `UNVERIFIED`다. 정상 조회에서 실제 빈 결과를 받은 경우만 확인된 0건으로 취급한다.
- 각 계획에 실제 보유·미체결·기체결 대조 및 기존 보호 기준 유지 정책을 결합한다. 구조화 보고서에서 이를 삭제·변경하면 게시를 거절한다. 게시기가 공통 보호 문구를 직접 붙여 작성자의 누락에도 유지한다.
- 신규 진입에는 연구 자료 및 거래량·진입 확인 재검증을 요구한다. 위험 축소에는 신규 매수용 현금·거래량 조건을 추가하지 않는다. 두 방향 모두 유효한 시세·장 운영·거래정지·소유 수량·미체결 확인은 필요하다.

보고서는 계속 주문 권한이 없으며 실제 보호 주문이나 계좌 위험 한도를 변경하지 않는다. 서로 다른 확인 방식의 손절선을 임의로 숫자 하나로 합치지도 않는다. 기존 규칙을 확인할 수 없으면 새 보고서가 이를 대체했다고 가정하지 않는다. 원본 보고서·연구·주문 원장의 시각과 내용은 수정하지 않는다.

## 검증과 운영 한계

외부 API 없는 회귀 검사는 정상·빈 연구, 미래·누락·잘못된·날짜만 있는 시각, 원본 불일치, 시세 갱신의 연구 승격 방지, 연구 미검증 계획의 게시, 보호 정책 변조 거절, 국내·미국 미체결 조회 실패, 위험 축소와 신규 진입 구분을 다룬다.
