# 일반 투자자를 위한 분석 전달 정책 재검토

## 결론

보고서를 읽을 수 있는 조건과 주문을 실행할 수 있는 조건이 혼합돼 있었다.
일반 투자자에게 필요한 것은 원분석의 방향, 검토할 가격 구간, 유효성 재검토 시점,
무효화와 비중 축소 조건이다. 보고서 작성·배포 과정 전체를 2분짜리 시세 유효기간 안에
끝내야 하는 설계는 이 목적에 맞지 않는다. 발행 실패를 반복적으로 복구하는 것보다
보고서 전달과 즉시 실행의 판단을 분리하는 것이 근본 해결이다.

## 확인한 원인과 범위

1. `work/pre_report.py`는 장 개장, 이번 producer에서 새로 관측한 시세와 VALID 계좌,
   36시간 이내 원분석, 전체 커버리지, 정상 source health를 모두 요구했다.
   `runtime.py`는 다시 읽은 뒤 검사하고 발행 직전에도 모든 행의 TTL을 검사했다.
   실증한 US packet의 producer 유효기간은 120초였다. 원시세 04:46:00 KST에 대해
   producer 종료 04:47:25, 최종 발행 04:47:54로, 성공 사례조차 시간 여유가 거의 없었다.
2. 네이티브 KR/US 자동화와 저장소 skill/prompt는 장 마감·신선도 실패 시 보고서를
   만들지도 ACK하지도 말라고 중복 지시했다. 코드만 바꾸면 기존 예약 지침이 다시 막는다.
3. 원결정 출력 예시는 10:30, VWAP, 상대거래량 1.2, 첫 30~60분 등을 기본값처럼 제시했다.
   장기 방향과 일봉 기반 조건부 계획도 초단기 조건을 기계적으로 쌓는 경향이 있었다.
4. 정상 사업 무효화 문장도 숫자·키워드 정규식에 걸렸다. 실제 GEV의 운전자본 반전과
   인수 조달·통합 부담에 대한 문장이 거부됐다. 투자 논지의 무효화는 가격에 한정되지 않는다.
5. 보고서 용량에 JSON 들여쓰기까지 산입했다. 실제 전체 종목 초안을 반복 줄이거나
   수동 재작성해야 했다. 입력에서도 원조건 중복 복사가 불필요한 팽창을 만들었다.
6. 시세 지연만이 유일한 장애 원인은 아니다. 다른 세션은 저장 경로 복구, 개별 종목의
   회사 식별/근거 무결성, 전체 분석과 Work 결과의 실제 배포를 복구했다. 그 검증을 취소하거나
   실패·누락을 성공으로 다시 쓰지 않았다. 최신 전달 성공과 이후의 구조적 개선은 별개다.

## 바뀐 계약

| 대상 | 발행 정책 | 계속 요구하는 것 |
|---|---|---|
| 일반 투자 보고서 | `prepare --report-policy investor`; 기본 CLI 경로 | 원자료 해시·종목 커버리지의 정확한 표시·검증 가능한 근거 날짜 |
| 지연·휴장·오래된 계좌 | 원시각을 표시하고 계획 발행 | 현재 가격이나 현재 주문 수량이라고 주장하지 않음 |
| 일부 종목 실패 | 확보된 종목 계획과 실패·누락 목록 발행 | COMPLETE로 바꾸거나 종목을 몰래 누락하지 않음 |
| 미래·누락·잘못된 원분석 날짜 | 해당 행을 자료 확인 대상으로 표시 | 검증 불가 논지·가격 조건은 근거에서 제외 |
| 시세 날짜 불명, 별도 날짜가 있는 원분석 | 시세값 제외, 검증된 원분석 조건 유지 | 원분석을 현재 가격으로 둔갑시키지 않음 |
| 모델 합성 지연·실패 | `draft-investor` 기본 보고서를 먼저 전달 | 새 모델 합성/외부 근거 재평가를 했다고 주장하지 않음 |
| 즉시 실행 확인 | 별도 `--report-policy execution --refresh-market` | 기존 달력·시세·계좌·위험·주문 검증 유지 |

투자 계획은 각 행의 `investment_plan`으로 봉인된다. 원분석의 방향과 진입·무효화 조건,
가격 구간, 규모 원칙을 보존하고 `execution`의 주문 동작은 비운다. 보고서가 발행된다고
현재 주문이 승인되는 것이 아니다. 날짜가 검증된 원문 조건은 특정 숫자·키워드가 없어도
허용하되, 보고서에서 임의로 조건·가격을 변경하지 못하도록 원 packet과 정확히 대조한다.

단기 7일 / 중기 30일 / 장기 90일은 분석 시점부터 계산하는 기본 **재검토 주기**다.
예측 보장이나 원래 주문 만료의 연장이 아니다. 새 실적·공시·중요 사건·무효화가 먼저
발생하면 그때 검토한다. 검토기한을 넘긴 계획도 숨기지 않고 재검토 필요로 표시한다.
실제 주문 트리거의 원래 유효시각은 따로 남는다.

원분석에 low/high가 있으면 그대로 사용한다. 단일 매수 BREAKOUT/PULLBACK 가격선만
명시적으로 표시한 1% **검토 여유폭**을 제공한다. 통계적 신뢰구간이나 체결 허용폭이 아니며
가격이 그 안에 있다는 사실만으로 매수하지 않는다. 손절·무효화·축소 가격은 넓히지 않는다.
숫자가 모순되거나 비가격 범위를 가격으로 잘못 추출한 항목은 해당 항목만 제외한다.
예: 가격 210 옆에 시간 범위 30~60이 low/high로 저장된 항목.

위험 축소 계획은 신규 매수와 별도로 먼저 보여 준다. 매도 가능 보유수량과 현재의 위험
조건을 확인하되, 신규 매수용 현금이나 상승 거래량 확인을 매도 제안의 전제에 붙이지 않는다.
향후 새 원분석도 일봉·종가·며칠 단위 계획을 기본으로 하도록 공통 정형 결정 지시를 수정했다.
과거 원분석의 보수적인 판단을 새 매수 승인으로 조용히 바꾸지는 않는다.

## 운영 및 검증

- 기존 `publish → ACK → handoff`와 content-addressed 원장/중복 방지/정확한 외부 전달
  검증을 유지한다. 발행은 성공했지만 데이터는 부분적일 수 있으며 둘을 별도로 표시한다.
- 보고서 작성만을 위해 producer를 실행하거나 진행 중인 생산자를 기다리지 않는다.
  가능한 경우 검증된 최신 canonical pointer를 읽고, 그렇지 않으면 기존 원자료 검색을 사용한다.
- 반복 조건은 source 참조를 사용하고, 투자 보고서에 필요 없는 사적 즉시 주문 overlay는
  제외한다. 원분석의 규모 원칙과 보유/관심 역할·계좌 기준시각은 유지한다.
- 용량은 compact JSON의 실제 내용을 기준으로 계산한다. 내용 상한과 비밀정보 필터,
  해시/바인딩 검증은 유지한다.
- 외부 API 없는 fixture 테스트는 지연·휴장일·120일 된 자료·부분 실패·빈 자료·날짜 오류,
  원문 훼손·범위/기간 변조·실행 승격·매도/신규매수 구분·비가격 사업 무효화를 검증한다.
- 실제 US/KR 30종목씩의 자료를 격리된 runtime/archive에서 구성하고 발행 경로까지 검증했다.
  실제 운영 반영·PR·외부 배포 결과는 해당 변경의 완료 기록으로 별도 확인한다.

이 변경은 전달 신뢰성과 판단 자료의 실용성을 높인다. 수익 증가를 검증한 결과가 아니며,
투자 결과는 이후 동일한 시점 기준의 성과 기록으로 평가해야 한다.
