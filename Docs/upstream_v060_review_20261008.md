# TradingAgents v0.5.1–v0.6.0 검토 및 선별 적용

검토일: 2026-10-08 (한국시간)

## 비교 기준과 결론

- 적용 대상: `nornen0202/TradingAgents`, 작업 시작 `950dca9c`.
- 참조 upstream: `TauricResearch/TradingAgents`의 v0.5.1 `b9567467`, v0.5.2 `4b300982`, v0.6.0 `1394a3f7`.
- [공식 변경 기록](https://github.com/TauricResearch/TradingAgents/blob/1394a3f72aa4393e1a98f51b382434c4b4c2d972/CHANGELOG.md), [v0.6.0 코드](https://github.com/TauricResearch/TradingAgents/tree/1394a3f72aa4393e1a98f51b382434c4b4c2d972)를 실제 구현과 대조했다.

## 데이터 정확도와 장애 처리

### Yahoo 뉴스

Search는 일반 검색 결과를 반환할 수 있으므로 제목에 종목명이 있다는 추측으로 채택하지 않는다. `relatedTickers`에 정규화된 대상 종목이 명시된 기사만 사용한다. null 기사 필드·잘못된 종목 목록 형식도 안전하게 처리한다. 회사 및 거시 뉴스의 날짜 범위는 시작일 00:00 이상, 종료일 다음날 00:00 미만이며 발행 시각이 없는 항목은 제외한다.

feed/search는 최근 표본이며 과거 아카이브를 보장하지 않는다. 대상 기간에 유효한 기사가 없으면 공급자 이용 불가로 처리하여 설정된 다음 공급자를 시도한다. 성공한 보고서에도 비포괄적 표본이라는 범위 정보를 표시한다.

### 과거 재무제표와 SEC

- 과거 날짜에는 현재 Yahoo/Alpha Vantage 회사 개요를 과거 자료처럼 사용하지 않는다.
- Yahoo 재무제표는 회계기간 종료일만으로 공개 시점을 증명할 수 없어 과거 분석에서 차단한다.
- Alpha Vantage 재무제표는 과거 분석 시 발행일 또는 제출일을 확인한 항목만 허용한다. 수정공시의 원래 버전까지 보장하지 못한다는 한계를 표시한다.
- 과거 미국 재무제표 요청은 SEC 경로를 우선한다. 한국 종목에는 SEC 경로를 사용하지 않는다. 과거 시점이 검증되는 한국 재무제표가 없으면 현재 수치로 대체하지 않고 자료 부재를 알린다.
- SEC companyfacts는 `end`와 `filed`가 기준일 이내인 항목만 선택한다. 나중에 나온 수정 수치는 이전 날짜 분석에 들어가지 않는다. 그 날짜까지 공개된 최신 수정본을 선택한다.
- 연간 재무제표는 연간 보고서에 포함된 기간을 대상으로 한다. 분기 수치와 6개월·9개월 누적 수치를 구분하며, 누적 수치에서 분기를 임의 계산하지 않는다.
- 자본적 지출 태그의 `PaymentsToAcquireProductiveAssets` 대체값을 지원한다. 통화와 주당 단위를 각 행에 표시하고, 금액은 백만 단위로 제공한다.
- 출력은 선택된 핵심 계정과 최근 8개 분기/4개 연간 종료일로 제한한다. 없는 값은 0으로 만들지 않는다.

SEC 요청에는 기존 `SEC_USER_AGENT` 또는 호환 별칭 `SEC_EDGAR_USER_AGENT`로 실제 연락처가 포함된 식별자를 설정하는 것을 권장한다. 기존 기본 식별자도 호환성을 위해 유지한다. [SEC API 설명](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)에 따른 companyfacts를 이용한다. US-GAAP 외의 IFRS·회사 전용 태그와 과거 시점의 종목 매핑까지는 지원하지 않는다. 따라서 모든 종목의 완전한 역사 재무제표를 보장하지 않는다.

### 함께 수정한 실패 경로

Alpha Vantage의 `Information`, `Note`, `Error Message`를 금융 데이터로 전달하지 않는다. 요금제/호출 한도, 잘못된 키, 서비스 장애를 구분하고 오류에 API 키나 요청 URL을 넣지 않는다. 가격 CSV 날짜 필터가 실패하면 전체 기간 원본을 반환하지 않고 대체 공급자로 넘어갈 수 있는 명시적 오류를 낸다. 날짜는 정확한 `YYYY-MM-DD` 형식을 요구하여 `2026-4-5` 같은 축약형으로 미래 날짜 검사를 우회하지 못하게 한다. Gemini 요청에는 기본 600초 제한을 추가하고 명시적 override를 유지한다.

## 실행 구조와 호환성

병렬 분석은 애널리스트별 하위 그래프에서 도구 대화 이력을 분리한다. 리서치 토론은 선택된 모든 애널리스트 보고서가 완료된 후 한 번 시작한다. 체크포인트 식별자에는 실행 구조와 설정이 반영되어 구구조 체크포인트를 잘못 재개하지 않는다.

기본은 순차 실행이고 `analyst_max_concurrency=2`이다. 병렬 설정은 다음 제약을 고려해야 한다.

- 공유 Codex 세션은 한 번에 한 모델 호출을 처리한다. 도구 I/O는 중첩될 수 있지만 API 제공자와 같은 모델 호출 병렬 속도 향상을 보장하지 않는다. 추가 Codex 프로세스를 자동으로 만들지 않는다.
- 병렬 애널리스트는 형제의 미완성 보고서를 보지 않는다. fundamentals 단계의 중간 통합 요약은 순차 실행보다 교차 분석 문맥이 적을 수 있다. 이후 연구·매니저 단계는 완료된 모든 보고서를 받는다.
- 종목 병렬 수와 애널리스트 병렬 수를 동시에 올리면 API 호출량이 증가한다. 기존 운영 설정값은 변경하지 않는다.

API 호출자는 `propagate()`를 사용하거나 `prepare_run()` 후 `invoke_run()` / `stream_run()`을 사용한다. 저수준 `graph.invoke()` / `graph.stream()` 직접 호출은 실행별 데이터 설정 wrapper를 우회한다. 그래프 재사용 시 이전 실행 상태가 새 실패 실행의 보고서로 저장되지 않도록 상태를 초기화한다.

보고서 작성기·의미 평가기·실행 요약 등 예약 실행의 부가 역할은 기존 공통 제공자 정책을 유지한다. 새 tier 제공자는 분석 그래프의 quick/deep/output 역할에 적용된다.

## 사용 예

프롬프트 없이 분석하고 Markdown·HTML을 저장한다. 다음 명령은 실제 모델/데이터 호출을 수행하므로 검증에서는 모의 모델을 사용했다.

```powershell
python -m cli.main analyze --ticker NVDA --date 2026-10-02 --analysts market,news --language Korean --save --no-show
```

`--no-html`로 HTML 저장을 생략하고, `--out`으로 보고서 디렉터리를 지정한다. `--quick-provider`, `--deep-provider`, `--output-provider`는 해당 모델 옵션과 함께 지정한다. `--parallel-analysts`로 병렬 분석을 선택할 수 있다.

예약 실행 TOML 예시:

```toml
[run]
tickers = ["NVDA"]
parallel_analysts = true
analyst_max_concurrency = 2

[llm]
provider = "codex"
quick_think_provider = "codex"
quick_model = "gpt-6.1-sol"
deep_think_provider = "codex"
deep_model = "gpt-6.1-sol"
output_think_provider = "codex"
output_model = "gpt-6.1-sol"
```

제공자별 자격 증명은 기존 설정 경로를 사용한다. 필요할 때 `quick_think_backend_url`, `deep_think_backend_url`, `output_think_backend_url`을 지정할 수 있다. 공통 endpoint를 다른 제공자에 자동 전달하지 않는다. Ollama·OpenRouter·xAI도 명시적 endpoint를 우선한다. Codex 전용 모델 환경변수는 실제 Codex 역할에만 적용하고, 공유 제공자가 다른 경우에도 Codex 역할이 있으면 기존 프로세스 수 제한을 유지한다. endpoint·인증키·로컬 경로는 공개 보고서 설정에서 제외한다.

## 보고서 보안과 재현성

프로젝트 기본 모델은 **Codex `gpt-6.1-sol`**이다. 분석 quick/deep/output, 보고서 writer, judge, 계좌 판단, YouTube 추출·검증·종합 및 예약 워크플로의 선호 모델을 함께 변경한다. [공식 Codex 모델 문서](https://learn.chatgpt.com/docs/models#recommended-models)의 정확한 모델 ID를 사용한다. 과거 기록이나 사용자가 명시적으로 선택할 수 있는 호환 모델 목록은 과거 모델을 유지할 수 있지만 현재 기본값과는 구별한다. 실행 환경의 자격 및 모델 가용성 검사는 기존 preflight를 사용하며, 모델이 없을 때 다른 모델로 조용히 대체하지 않는다.

실제 실행 환경도 확인했다. 기존 `codex-cli 0.156.1`의 모델 목록에는 요청 모델이 없어 사전검사가 실패했다. 공식 `@openai/codex 0.161.0`을 프로젝트의 무시된 `.runtime/codex-cli`에 별도 설치하고, 프로젝트 `.env`, 기존 사용자 `CODEX_BINARY` 환경변수와 GitHub 저장소의 같은 변수를 새 실행 파일로 연결했다. 데스크톱 앱 실행 파일이나 Codex 전역 설정 파일은 변경하지 않았다. 새 프로세스에서 정확한 모델의 인증·가용성 확인과 프로젝트 `CodexClient`를 통한 짧은 응답 검증이 성공했고 모델 대체는 없었다. 기존 터미널은 이전 환경변수를 보유할 수 있으므로 다시 열어야 한다. 이미 진행 중인 분석은 중단하지 않았다.

HTML은 외부 스크립트·이미지·스타일시트 없이 읽을 수 있는 단일 파일이다. 모델이 출력한 HTML은 escape하고, 링크는 HTTP(S)/문서 내부 앵커만 허용하며 CSP로 실행·외부 자원 로딩을 제한한다. 기존 Markdown 반환 경로와 섹션 파일을 유지한다. 설정은 종합 보고서 부록과 별도 JSON에 기록하고 섹션 조각의 기존 형식은 유지한다.

설정은 allowlist로 내보낸다. 패키지 버전, 선택 애널리스트, 실제 등급별 제공자·모델, 토론 수, 데이터 공급자, 언어, 병렬 여부 등이며 전체 설정을 무차별 직렬화하지 않는다. 그래프 상태 로그에도 같은 공개 설정을 남긴다. 설정을 저장한다고 외부 데이터의 역사 스냅샷과 LLM 출력을 완전히 재현할 수 있는 것은 아니다.

## 유지한 기존 강점과 남은 범위

기존 walk-forward 평가의 다음 세션 진입, 거래비용, 비교 기간 일치, 미래 결과 기억 차단 및 중첩 cohort 비복리 처리는 유지한다. 구조화된 최종 판단 스키마도 유지하므로 upstream의 자유서술 `Rating:` 파서를 교체 도입하지 않는다.

기존 성과 추적은 시장 필터, 가격 조회 범위와 여러 기간의 결과 갱신을 가진다. upstream의 단일 보유기간 memory settlement로 대체하거나 분석 도중 새로운 학습 기억을 자동 추가하면 평가 의미와 재실행 동작이 바뀐다. 이번 변경에서는 정산 엔진을 병렬화하지 않는다. 정산 비용·실패율을 별도로 측정한 뒤 거래일·벤치마크·중복 기록 정책을 유지하는 독립 작업으로 다루는 것이 적합하다.

모델 사전학습의 미래 지식, Yahoo 조정주가와 생존 종목 편향, 공개일까지만 확인 가능한 공급자의 수정 이력은 여전히 백테스트 한계다. 날짜 필터 강화만으로 완전한 인과적 백테스트가 되지는 않는다.

## 검증

GitHub의 기존 Dependabot 경고 13건은 잠금 파일의 네 패키지에 해당했다. 전체 의존성을 일괄 갱신하지 않고 보고된 수정 버전인 `langgraph-sdk 0.4.4`, `multidict 6.9.1`, `pypdf 6.19.0`, `urllib3 2.8.0`만 잠금 파일에 반영했다. 새 HTML 렌더링의 `markdown-it-py`는 기존 전이 의존성을 명시적 의존성으로 선언했다.

단위·통합 회귀 검사에서는 외부 LLM과 실제 투자 판단을 호출하지 않는다. Yahoo 장애/태그/날짜 경계, SEC 수정공시/기간/단위, 공급자 대체, 실행 설정 격리, 병렬 완료 장벽, 체크포인트, CLI 비대화형 동작, 한국어 보고서와 HTML 안전성, 예약 설정 전달을 검증한다. 모델 전환에 한해 실제 `gpt-6.1-sol`로 고정 문구를 반환하는 짧은 연결 검사를 별도로 수행했다. 투자 분석이나 주문은 실행하지 않았다.

360·390·430px 모바일 화면, 전략 상호작용, 보고서 탐색의 기존 브라우저 회귀 검사가 통과했다. 새 HTML은 360px/1440px에서 긴 한국어 제목·표·목차, 가로 넘침, 스크립트 및 외부 자원 미로딩을 확인했다. 로컬 전체 검사에서는 이 변경과 관계없는 저장공간 정리 테스트 2개가 실제 Windows Runner.Worker의 경로 조회 제한 때문에 안전하게 정리를 중단하여 실패한다. 운영 보호장치를 우회하거나 실제 작업자를 중단하지 않으며, 최종 전체 검사와 GitHub CI 결과는 PR 본문에 기록한다.
