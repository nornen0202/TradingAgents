# 검증 통과 후 국내·미국 KIS 전략 지속 모의매매

기존 TradingAgents 실행 판단과 주문 제안을 전용 KIS 모의계좌에 연결한다. 별도 Workbench나 새로운 투자 판단 모델은 만들지 않는다. 실계좌 자동 주문은 비활성으로 유지한다.

## 활성화 조건과 기존 기능의 연결

`LocalAutomation-strategy-kis`가 매분 실행된다. 국내·미국별로 기존 유한 검증 캠페인의 주문 접수·체결·취소가 모두 확인되어야 신규 전략 주문을 허용한다. 화면의 성공 표시만 신뢰하지 않고 원래 캠페인 상태, 불변 주문 조건, SQLite 브로커 관측, 모의계좌 소유자 식별값을 다시 대조한다. 모의 키·계좌가 바뀌면 기존 검증으로 활성화하지 않는다.

기존 `decision_bundle_v2.json`과 `portfolio-private/proposed_orders.json`을 `archive_paper.build_step`으로 읽는다. 성공 완료된 실제 분석, 현재 실행 가능 판정, 같은 종목·방향의 명시적 제안, 원래 발행·관측·만료 시각을 모두 요구한다. 새로운 시세를 가져와 오래된 판단을 새 판단으로 바꾸지 않는다. 실행 신호·가격·계좌의 120초 기준과 원래의 더 이른 만료를 보존한다.

방향은 기존 STARTER/ADD/BUY, REDUCE/EXIT/TAKE_PROFIT 실행 판단을 따른다. 주문 수량은 기존 제안 이하이며, 모의계좌의 실제 가용 현금·매도 가능 수량·집중도와 다음 초기 한도로 제한한다.

| 항목 | 국내 | 미국 |
|---|---:|---:|
| 지정가 주문당 한도 | 10만원 | 500달러 |
| 일일 신규 매수 합계 상한 | 30만원 | 1,000달러 |
| 일일 원주문 수 상한(매수·매도 합계) | 3건 | 3건 |
| 종목 집중도 상한 | 35% | 35% |

1주 가격이 주문 한도보다 높으면 주문하지 않는다. 미국은 명시적 제안 수량이 없을 때 날짜 있는 증권사 기준환율로 원화 제안 예산의 달러 한도를 계산한다. 확인할 수 없으면 차단한다. 실제 자금은 모의계좌 USD 현금만 사용하며 자동 환전·신용·공매도·시간외·시장가 주문은 하지 않는다. 허용 종목은 기존 포트폴리오 관심목록으로 고정하며, 미국 거래소는 날짜 있는 해당 거래소 시세 응답으로 확인한다.

## 주문의 지속 운용

시장당 한 번에 전략 주문 하나만 미완료 상태로 유지한다. 기존 주문부터 대조하고 신규 후보는 위험 축소 매도를 먼저 검토한다. 같은 실행 보고서·종목·방향은 영구 식별자로 한 번만 소비한다. 네트워크 전송 전에 시도를 저장하며, 재시작 후 UNKNOWN이나 전송 직전 중단 기록을 다시 보내지 않는다.

미체결 잔량은 5분 경과, 장 마감 10분 전, 중지 설정 또는 검증 조건 상실 시 취소를 확인한다. 취소 요청 접수와 실제 취소 확인은 별도 상태다. 부분체결은 누적 수량·금액의 변화를 검증하고 중복 합산하지 않는다. 이전 거래일의 미완료 주문은 대조 결과가 확정될 때까지 신규 주문을 막는다. 통신 오류·조회 제한·불명확한 응답은 숨기지 않고 대기/차단으로 표시한다.

전략이 실제로 매수해 확인한 수량까지만 매도한다. 연결 검증용 주문, 수동 보유분, 기존 내부 가상체결은 전략 보유 수량과 성과에 넣지 않는다. 기존 내부 모의매매 작업과 원장은 계속 독립적으로 운용된다.

## 투자자가 확인하는 화면

기존 `http://127.0.0.1:8766/`의 **KIS 전략 지속 모의매매**에서 시장별 검증 통과 여부, 최근 점검, 대기·차단 이유를 확인한다. 주문 표에는 종목·원래 전략 실행 ID, 매수/매도, 주문/체결 수량, 지정가/실제 누적 평균 체결가, 주문 상태, 취소 접수/확인, 마지막 관측 시각이 나온다. 계좌번호·키·토큰·브로커 주문번호는 공개하지 않는다. 화면은 읽기전용이다.

성과는 해당 전략의 **확인된 매도 대금 − 매수 대금 + 남은 전략 보유 수량의 최신 시세 평가**다. 국내 KRW와 미국 USD를 분리하고 최근 확인한 평가 이력을 보존한다. 지정가를 실제 체결가로 대체하지 않는다. 누적 체결 금액이 없거나 시세가 오래됐으면 현재 손익은 미확인으로 표시하며, 이전에 확인한 평가 기록은 원래 시각으로 보여 준다. 비용과 정산을 확인하지 않았으므로 순손익·계좌 전체 수익률·정산 성과로 표현하지 않는다.

## 운영·검증

설치: `tools/install_kis_strategy.ps1 -EnableDemoStrategy`. 기존 분석·발행·내부 모의매매·유한 검증 작업의 주기는 바꾸지 않는다. 작업은 `fork/main`의 불변 소스 스냅샷을 사용한다. 설정은 `.runtime/local-automation/kis-strategy/enabled.json`의 `KIS_DEMO_STRATEGY`, 명시적 활성, 실주문 비활성을 모두 요구한다.

신규 주문 중지: `.runtime/local-automation/kis-strategy/HALT`. 중지 중에도 기존 주문의 대조·취소 정리는 진행한다. 유한 검증의 HALT도 신규 전략 주문을 차단한다. 상태·원장을 지워 재실행 한도나 불명확한 주문을 우회하지 않는다.

실제 운영 결과는 `archive/paper/kis-strategy-runtime.json`, 시장별 `kis-strategy/*-strategy.sqlite`, 예약 작업 완료 기록과 화면을 대조한다. 로그에는 상태·시각·횟수만 기록한다. 기존 이 채팅 후속 점검이 정규장 검증 이후 지속 전략 매매의 신호 연결, 차단 이유, 실제 주문·체결·취소, 성과 근거를 확인해 보고한다. PC 전원과 Windows 로그인이 필요하고 채팅 후속 보고에는 Codex 앱 실행이 필요하다.

2026-10-18은 휴장이므로 실제 장중 체결·취소·성과는 이후 정규장 관측으로 확인해야 한다. 오프라인 검증은 두 시장의 실제 전송 계층을 모의 HTTP 응답으로 실행하고, 승인 전 무통신, 실제 조건 충족 후 주문, 재시작/중복/응답 유실, 부분체결/취소, 미래·누락·잘못된 시각, 계좌 불일치, 모의 자금·보유 한도, 금액 누락·역행, 화면의 과거 시점 필터링을 확인한다.

체결 금액 필드는 KIS 공식 [국내 주문체결 조회](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_ccld/chk_inquire_daily_ccld.py)의 `tot_ccld_amt`, [미국 주문체결 조회](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_ccnl/chk_inquire_ccnl.py)의 `ft_ccld_amt3`를 사용한다. 해당 값과 체결 수량·원주문 조건이 검증되는 경우에만 금액 성과에 반영한다.

## 2026-10-19 정규장 운영에서 확인한 보완

- Windows 예약 작업은 Codex MSIX 앱의 가상화된 LocalAppData 저장소를 공유하지 않을 수 있다. 이번 운영에서는 앱 안에서 보이던 DPAPI 설정이 예약 작업에서는 존재하지 않았다. 사용자 범위 DPAPI 암호문만 실제 사용자 저장소에 복사하고, 예약 작업과 동일한 실행 계정에서 국내·미국 설정 복호화와 브로커 생성까지 검증했다. 평문 키를 저장하거나 계좌 정보를 출력하지 않았다.
- 국내 VTS는 취소 완료 후 원주문에 `cncl_yn=N`, `cncl_cfrm_qty=1`, 잔량 0을 반환하고, 별도 취소 주문 행에 `cncl_yn=Y`를 표시했다. 원주문의 확인 취소 수량과 원주문 수량·체결·잔량이 일치할 때만 취소 완료로 해석한다. 잔량 0만으로는 취소로 간주하지 않는다. 기존 주문 식별자와 원장을 유지한 읽기 조회로 복구하며 재주문하지 않는다.
- [KIS 공식 일별주문체결조회 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_ccld/chk_inquire_daily_ccld.py)의 취소확인수량 별칭 `cnc_cfrm_qty`도 지원한다. 두 필드가 함께 오면 값이 같아야 한다. 누락·음수·비정상 형식·불일치·미래 또는 잘못된 주문시각은 검증을 우회할 수 없다.
