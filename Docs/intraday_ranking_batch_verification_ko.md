# 장중 거래소 순위 조회의 배치 공유와 검증

## 확인한 중복

미국 장중 자료 수집은 종목마다 독립 공급자와 KIS 클라이언트를 만든다. 가격·호가·체결 자료는 종목별 요청이지만 `overseas_volume_power`는 종목 인자가 없는 거래소 순위 요청이다. 같은 거래소의 30종목을 재현한 작은 오프라인 Mock에서 실제 메서드는 같은 endpoint와 전체 인자로 30번 호출됐다.

요청은 `GET /uapi/overseas-stock/v1/ranking/volume-power`, TR `HHDFS76280000`이다. 예시의 전체 params는 `EXCD=NYS`, `NDAY=0`, `VOL_RANG=0`, `AUTH=''`, `KEYB=''`이며 `tr_cont=''`다. exchange·nday·volume_range·keyb·auth·tr_cont가 다른 여섯 경계에서는 각각 다른 요청임을 확인했다. 이는 코드와 Mock의 호출 수 증거이며 운영 API의 실제 RTT를 측정한 결과는 아니다.

## 공유 범위

같은 체크포인트의 한 수집 배치 안에서 동일한 요청의 성공 응답만 공유한다. 환경·접속 호스트·자격증명 범위와 endpoint·TR·전체 params·연속 조회 인자가 모두 일치해야 한다. 동시에 요청하더라도 동일 키의 성공 응답은 한 번 받아 각 소비자에게 별도 복사본으로 전달한다.

각 종목의 공급자·KIS 클라이언트·세션은 독립적으로 유지한다. 가격·계좌·주문 요청은 공유하지 않는다. 배치가 끝나거나 제한 시간을 넘으면 공유 상태를 폐기하며 다음 체크포인트에서 다시 조회한다. 오류·빈 응답·잘못된 응답을 성공 결과로 저장하지 않고 원래 재시도와 선택 자료 누락 처리를 유지한다.

원문의 날짜·시각·헤더는 그대로 보존한다. 최초 응답이 실제 완료된 aware UTC 수집시각은 별도 영수증으로 한 번만 기록한다. 후속 소비자의 처리시각으로 바꾸거나 과거 응답을 새로운 조회처럼 표시하지 않는다. 이 수집시각은 거래소 원천 시각이나 체결시각을 대신하지 않는다. 원래 시점 검사·120초 제한·매매 승인·한도·계좌 소유권·주문 원장은 변경하지 않는다.

## 실제 장중 실패와 구분

PR #440 이후 고정 관측창은 2026-10-22 23:24:43.278129~23:39:43.699902 KST, 900.4초 후 실패했다. 새 완료 자료 10개가 두 소비자에게 전달됐지만 360개 관측에서 전체 만료 16개·부분 만료 22개 샘플이 있었다. 버전·소비자 시계 오류는 0개다. 반복 관측 수를 독립 생산 실패 횟수로 해석하지 않는다.

첫 부분 만료의 source `233032`는 23:31:13.108에 완료했다. 23종목의 가장 오래된 근거는 분봉 23:30:00, 나머지 7종목은 halt 발행 23:30:49였다. 다음 source `233136`은 23:32:36.638에 완료했다. 첫 전체 만료의 source `233416`은 23:34:58.309에 완료했지만 전체 30종목의 가장 오래된 근거가 halt 발행 23:33:48이라 23:35:48에 만료됐다. 다음 source `233539`의 완료는 23:36:26.566으로 38.566094초의 공급 공백이 생겼다.

다음 생산 완료와 소비자 `checked_at`의 차이는 각각 7.183735초·8.412038초다. `waited_seconds`는 15.021초·15.000초지만 정확한 대기 종료 wall clock이 없어 위 차이를 대기 종료와의 차이라고 단정하지 않는다. 만료 시각을 뒤로 옮기거나 원천 시각을 다시 쓰지 않는다.

원본 `open-session-440-us-20261022T2325.json`의 SHA-256은 `914c3196f1f54be582b7d6aef6ca254aa5f347115e7bb3ce047af667bfbada99`다. 별도 `open-session-440-us-causal-audit-20261022.json`은 생산 manifest·bundle·snapshot 해시와 시각 비교를 보존한다. 실패한 관측창을 덮어쓰지 않는다.

## 완료 기준과 한계

외부 API 없는 검사는 동일 거래소 요청 횟수, 전체 키·자격증명 격리, 성공 복사본의 변경 격리, 실패 후 재조회, 다음 배치의 새 조회, 동시 요청과 종료 시점을 확인해야 한다. 새 시각 영수증은 정상·미래·누락·잘못된 시각을 검증하고 원천 시각과 구분해야 한다. KR와 직접 호출 경로, 종목별 가격 요청 수 및 결정론적 위험 동작도 보존해야 한다.

최종 관련 6개 테스트 파일은 192개·하위 검사 23개를 통과했고 Ruff·diff 검사 및 독립 리뷰를 통과했다. 실제 메서드의 같은 거래소 30개 독립 클라이언트 요청을 1회로 줄이면서 payload·header 깊은 복사, 전체 인자와 인증 범위 격리, 실패 재조회, 배치 종료와 늦은 응답 폐기, 다음 배치 새 조회를 확인했다. 전체 snapshot 비교에서 새 영수증 외 가격·판정 근거는 같았고 비등재 종목의 원래 결과도 보존했다. 원문의 미래·누락·잘못된 시각은 수집시각으로 정상화하지 않으며 새 영수증은 `event_time_verified=false`로 원천 시각 증명이 아님을 명시한다. 이 수치는 오프라인 검증이며 최종 head CI와 운영 결과를 대신하지 않는다.

개별 API RTT·CPU·파일 작업의 기여도는 아직 계측하지 않았다. 중복 순위 조회를 실제 장중 만료의 유일한 원인으로 단정하지 않으며, 호출 수 감소를 신선도 기준 통과로 간주하지 않는다. 최종 커밋 검사와 배포 이후 새 고정 관측창에서 최소 600초·새 공동 자료 3개 이상·전체 및 부분 만료 0을 별도로 확인해야 한다.

정상 전략 BUY·SELL, 국내 검증 왕복과 실제 비용·정산·반복 표본은 별도 미충족 기준이다. 이 변경을 체결 성공이나 실투자 준비 완료로 표시하지 않으며 실계좌 주문과 실제 투자 자동 전환은 비활성이다.
