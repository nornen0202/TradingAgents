## 실제로 확인한 문제

2026-10-25 15:17 KST 현재 운영 화면에서 `/api/kis-strategy-health`는 0.292초에 응답했지만 `/api/tickers`는 20.015초에 시간 초과했다. 종목 목록이 비어 보여도 분석이 없다는 뜻이 아니었다. 원문 manifest 전체를 최대 2,048개 캐시에 유지하고, 과거 실행별 종목 경로를 반복 검사하며, 목록 완료 전 진행 상태도 표시하지 않는 경로가 있었다. 당시 정상 KR/US 전략 체결은 모두 0이었다. 일요일의 `MARKET_CLOSED`를 새 주문 장애로 계산하지 않는다.

## 변경한 조회 경로

화면 서버당 하나의 읽기 전용 스캐너가 manifest의 선택용 필드만 보관한다. 새 요청은 추가·삭제·변경된 파일을 확인하며 변경되지 않은 원문은 다시 JSON 해석하지 않는다. 파일 크기·mtime·ctime·파일 식별자는 캐시 무효화용이며 자료의 가용 시각이나 변조 방지 증명을 대신하지 않는다. 데이터 선택은 매 요청의 timezone 있는 기준 시각과 원래 생산 시작·완료 시각을 다시 비교한다. 잘못되거나 관측 중 바뀐 원문은 이전 캐시로 복구해 성공처럼 보이지 않는다.

조회가 0.2초 안에 끝나지 않으면 HTTP 202로 실제 확인한 manifest 수와 스캔 세대를 돌려준다. 같은 세대의 폴링과 다른 탭은 진행 중인 한 스캔에 합류한다. 오래된 폴링 토큰이 새 스캔을 반복 생성하지 않는다. 최신 후보부터 검사하며 최신 경로가 유효하지 않으면 더 오래된 유효 원본을 확인한다. 종목 이름만 요청한 경로는 analysis·차트·이벤트 원문을 읽지 않는다. 운영 API와 주문 경로에는 이 인덱스를 사용하지 않는다.

화면은 처음부터 진행 상태를 표시하고 각 운영 API가 끝나는 대로 독립적으로 그린다. 개별 네트워크 요청은 15초, 목록 진행 폴링은 최대 120초로 제한한다. 수동 재조회는 이전 브라우저 요청을 취소한 뒤 서버의 기존 스캔에 합류한다. 1분 자동 새로고침은 현재 조회가 끝날 때까지 건너뛴다. 빈 자료·서버 오류·시간 초과 뒤에도 재조회가 가능하고 오래된 조회의 오류가 새 결과를 덮지 않는다. 브라우저 취소로 연결이 끊기면 서버가 두 번째 오류 응답을 쓰지 않는다.
