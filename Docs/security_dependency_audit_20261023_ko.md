# 2026-10-23 외부 입력 처리 의존성 점검

정상 전략 체결과 수익 검증을 재점검하면서 저장소의 열린 Dependabot 경고도 확인했다. 16시대 조회 결과 17건이며 `certifi` 1건(critical), `aiohttp` 8건(high 3, medium 3, low 2), `pypdf` 8건(medium 7, low 1)이었다. 이는 이 프로젝트에서 실제 공격이나 피해가 발생했다는 증거가 아니다.

| 패키지 | 기존 잠금 버전 | 실제 운영 설치 버전 | 수정 잠금 버전 |
|---|---|---|---|
| certifi | 2026.6.17 | 2026.6.17 | 2026.10.19 |
| aiohttp | 3.14.3 | 3.14.1 | 3.14.4 |
| pypdf | 6.19.0 | 6.19.0 | 6.21.1 |
| yarl | 1.24.2 | 1.24.2 | 1.25.1 |

`aiohttp`의 실제 설치가 잠금 파일보다 오래됐다는 점도 확인했다. 소스 배포가 패키지 배포를 대신하지 못한다. 이번 변경은 세 취약 패키지의 최소 버전을 선언하고 잠금 파일을 다시 생성한다. `yarl>=1.25.1,<2`는 새 aiohttp의 요구 조건이므로 함께 변경한다. 그 외 잠금 패키지 버전은 유지한다. API 키, 인증서 검증 옵션, 주문 환경, 계좌·승인·한도와 원장은 변경하지 않는다.

공식 근거:

- [certifi GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2): 손상된 중간 인증기관 키와 관련된 emSign 신뢰 루트, 수정 버전 2026.10.19.
- [aiohttp 3.14.4](https://github.com/aio-libs/aiohttp/releases/tag/v3.14.4): HTTP 입력·자원 소비·쿠키 처리 관련 보안 수정.
- [pypdf 6.21.1](https://github.com/py-pdf/pypdf/releases/tag/6.21.1): PDF 및 이미지 입력 처리 수정. 저장소 경고 8건의 수정 하한 중 가장 높은 버전을 적용한다.

운영 환경을 바로 변경하지 않고 격리된 패키지 디렉터리에서 TLS 검증 컨텍스트, 비동기 클라이언트 생성, 한 페이지 PDF 쓰기/읽기, URL 처리를 확인했다. 모의 KIS 전송·시점·조회/주문 경계와 PDF/Telegram 관련 오프라인 회귀는 430개와 하위 검사 23개가 통과했다. 잠금 파일 검사·내보내기·네 패키지 외 버전 불변 검사도 통과했다. 전체 CI는 잠금 파일에서 추출한 제약으로 설치하므로 실제 변경 버전으로 검증한다.

운영 반영은 별도 단계다. 실행 중인 연구·주문 작업을 중단하지 않으며 기존 진입 잠금과 프로세스 소유권을 확인한 뒤 정확한 네 버전만 반영한다. 설치 버전·원래 승인과 한도·작업 정의·모의 원장을 전후 대조한다. 장기 실행 중인 읽기 전용 화면 서버의 새 코드 반영은 해당 서버만 확인해 재시작하며 다른 앱·CI 작업은 건드리지 않는다. 저장소 경고 해소와 실제 설치 검증을 구분해서 기록한다.

보안 패치가 필수 연구 자료, 정상 전략 승인·체결, 비용·정산 또는 투자 수익성을 증명하지는 않는다. 실계좌 주문과 자동 전환은 계속 비활성이다.
