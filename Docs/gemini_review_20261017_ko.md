# 제미나이 코어 리뷰 검토 및 개선 결과

2026년 10월 17일 기준 `c4d02017`의 실제 코드와 오프라인 테스트를 대조했다.
리뷰는 툴 호출 제한과 시점 무결성의 필요성을 짚었지만, 병렬 실행·체크포인트 해시·정형 출력·국내 데이터 연동 일부를 미구현으로 설명했다.
이미 있는 경로는 유지하고, 확인된 결함을 수정했다. 실거래 주문 경로와 운영 모델 선택은 이번 변경 대상에 포함하지 않았다.

## 실행 동작과 설정

툴 한도는 개별 Tool 개수가 아닌 요청 묶음 단위다. 한 번에 세 Tool을 요청하고 세 결과를 받으면 1회로 센다.
한도 도달 후에는 추가 Tool 없이 수집한 근거를 요약하며 수집 제한을 표시한다. 공급자가 요약 대신 다시 Tool을 요청해도 실행하지 않는다.
최종 텍스트가 비어 있으면 수집한 자료와 불완전성을 명시한 보고서를 반환한다.

기본 `max_recur_limit`은 200으로 조정했다. 네 애널리스트가 각각 15회까지 수집한 뒤 토론·판단을 마칠 여유를 확보하기 위한 값이다.
사용자가 명시한 더 작은 전체 제한은 그대로 적용되므로 개별 수집 상한에 도달하기 전에 실행이 중단될 수 있다.
기존 버전 2 체크포인트는 새 식별자로 자동 재개하지 않으며 새 실행을 시작한다.

모의매매의 `max_drawdown`은 기본 비활성이다. 새 실험의 한도 JSON으로 선택하며,
기존 원장의 한도를 바꾸어 성과를 이어 붙이지 않는다. 상세 동작은 [모의매매 한도 안내](kis_demo_execution_ko.md)에 설명했다.
정형 출력 복구가 소진되면 `STRUCTURED_DECISION_INVALID`, 기존 Codex 전송 장애 경로는 `CODEX_PROVIDER_UNAVAILABLE`로 기록한다.

## 적용하지 않은 확장과 한계

PyKRX 기반 20거래일 외국인·기관 누적 수급, 신용·대차잔고, DART 재무 주요계정의 시점별 원본 복원은 추가 기능이다.
기존 KIS 장중 수급과 같은 자료로 간주할 수 없으므로 별도의 거래일·수정 이력·가용 시각·권한 계약을 갖춘 어댑터로 구현해야 한다.
이번에는 검증되지 않은 시계열을 분석에 주입하지 않았다.

수치 레짐 가중치는 날짜가 검증된 변동성·추세·섹터 메타데이터 생성 경로와 검색 품질 평가가 먼저 필요하다.
LLM 보고서의 숫자나 표현을 파싱해 확정적인 시장 국면으로 저장하지 않았다.
메모리는 `memory_max_entries` 범위의 순환 저장소다. 보존된 문서 안에서 미래 기록이 과거 점수에 영향을 주지 않도록 수정했지만,
오래된 기록의 삭제를 막는 전체 백테스트용 시점별 아카이브를 새로 구축한 것은 아니다.

리뷰의 ATR 예제는 손절 폭을 일괄 확대하고 신뢰도를 비중으로 환산한다. 입력 검증·계좌 보유 비중·거래 단위·검증된 가격 기준이 빠져 있어 그대로 적용하지 않았다.
누적 낙폭 검증은 실제 수치를 보유하는 모의매매 경로에 추가했으며 실계좌의 거래 권한이나 주문 동작을 변경하지 않는다.

DART `rcept_dt`는 일자 단위다. 날짜 범위 검증은 장중 특정 시각에 공시가 이미 공개되었다는 증거가 아니므로,
장중 백테스트에는 별도 공개 시각이 필요하다. API의 접수일·상태 코드 정의는 [OpenDART 공식 공시검색 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)를 따른다.

## 검증 범위

새 회귀 테스트는 외부 API 없이 순차·병렬 툴 반복 종료, 체크포인트 재개, 메모리 점수의 시점 격리,
정산 날짜, 다섯 메모리 소비 노드, 공시 응답 날짜·오류, 출력 실패 상태, 모의매매 낙폭·부분 시세·거래 비용을 확인한다.
프로젝트 `.venv`에서 전체 테스트 2,675개와 하위 테스트 131개가 통과했고, 1개는 건너뛰었다.
정적 검사(`ruff check . --select E9,F63,F7,F82`)와 공백 검사도 통과했다.
CI의 모바일 레이아웃, 전략 상호작용, 리포트 읽기·탐색 회귀 검사를 실행해 모두 통과했다.
모바일 폭은 360·390·430px이며 전략·리포트 검사는 1440px도 포함한다.
외부 데이터 API와 실제 LLM 공급자의 가용성은 오프라인 회귀 테스트의 검증 대상이 아니다.
