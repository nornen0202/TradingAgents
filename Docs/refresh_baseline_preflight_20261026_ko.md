# 연구 준비 대기와 시세 갱신 재시도 분리

기준일: 2026-10-26. 이 변경의 성공 기준은 준비되지 않은 연구 때문에 갱신 예산을 소모하지 않는 것이다. 정상 전략 승인·증권사 체결·수익성 검증은 별도 결과다.

## 관측한 문제

국내 분 단위 시세 생산자는 적격 완전 연구가 없었던 09시대에 세 번 실패했다. 기존 `execution-refresh/kr.json`은 09:10:05 시작, 실패 3회, `RuntimeError`를 기록한다. 이후 원래 일일 연구의 세 번째 시도가 10:43:49에 30/30종목으로 완료되어도, 그날 이미 소진한 갱신 예산은 복원되지 않는다. 14:30 overlay를 두 소비자가 채택했지만 120초 이후에는 다시 만료된다. 이 상태에서는 원래 장중 재분석 입장 창에도 신선한 관측을 제공하지 못할 수 있다.

수정은 기존 runner와 같은 완전 연구 선택 조건으로 실행 준비 여부를 먼저 확인한다. 적격 연구가 없으면 준비 대기를 반환하고 갱신 시도 영수증을 쓰거나 executor를 호출하지 않는다. 조회 오류 역시 실행 준비 완료로 간주하지 않는다. 기존 cooldown과 실패 횟수 상한을 먼저 적용하므로 이미 소진한 예산은 그대로다. 실제 실행 시 runner의 원래 검증을 다시 거친다.

완전 연구 선택은 실행 승인이 아니다. 원래 연구 커버리지·시장·96시간·거래 세션·미래 시계 오차 기준을 보존하고, 주문의 필수 자료·원래 판단·종목 허용 목록·소유권·시세·계좌 TTL·잠금·한도 검사는 유지한다. 사전 점검은 완전 연구의 존재를 확인하며, 실제 요청 종목과 필수 보유 종목의 커버리지는 실행 시 runner가 다시 확인한다. 원본 연구·승인 시각을 갱신하지 않는다.

## 수용 기준

- 완전 연구 없음·만료·부분 완료·원래 허용 오차를 넘는 미래 시각·시장 불일치에서 실행하지 않고 원래 시도 영수증과 예산을 보존한다.
- 준비 대기는 실행 성공이나 새 승인으로 표시하지 않는다. dry-run도 같은 준비 조건을 사용한다.
- 적격 연구가 생기면 원래 시장창·cooldown·실패 예산 안에서만 실행한다. 실행 중 실패는 원래 방식으로 집계한다.
- 필수 자료가 부족한 종목, 원래 WAIT 결정, 허용 목록 밖 종목, 전략 소유 보유분 없는 매도는 계속 차단한다.
- 배포는 기존 source mutex를 사용하고 원래 승인·소유권·한도·7개 Windows 작업 정의의 전후 증거를 비교한다.
- 실제 장중 연속 신선도와 정상 BUY/SELL 체결은 운영 영수증으로 따로 검증한다. 과거 실패 창이나 소진 예산을 변경하지 않는다.

## 현재 목표와의 관계

국내 별도 검증 왕복은 10월 23일 BUY 1주 84,195원, SELL 1주 83,845원, 총손익 -350원으로 확인된 기존 결과다. 만료된 캠페인을 재개하지 않는다. 이 거래는 정상 전략 성과에 합산하지 않는다.

10월 26일 국내 full 연구의 실행 커버리지는 30/30이지만 필수 도구 근거는 28/30이다. 411080.KQ와 079650.KQ의 공시 근거가 미확인이고 두 종목 모두 기존 주문 허용 목록 밖이다. 원래 판단은 30개 모두 WAIT/NONE이며, 정상 국내·미국 전략 주문·체결은 현재 0이다. 자료 회복 또는 이 수정만으로 BUY/SELL을 보장하지 않는다.

정상 전략의 원래 진입·청산 승인, 증권사 모의 체결, 귀속된 실제 비용·정산, 반복 표본·기간 외 검증이 남아 있다. 실계좌 주문과 자동 전환은 비활성이며 투자 준비 판정은 `NOT_READY`를 유지한다. 테스트·CI·배포의 실제 결과는 `.runtime/local-automation/live-verification/`의 새 영수증에 기록한다.
