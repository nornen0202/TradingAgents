# 기존 검토 화면·지속 모의매매·자연어 조건·실험 카드 운영

2026-10-18 KST. 사용자 지시에 따라 기존 TradingAgents 안에 운영 경로를 연결한다. 실계좌 자동 주문은 활성화하지 않는다. 별도 Workbench 프로젝트를 만들지 않는다.

## 투자자가 확인할 곳

같은 PC의 `http://127.0.0.1:8765`는 개인용 읽기전용 검토 화면이다. 기존 공개 보고서와 구분한다. 가격·원 분석 완료 시각·현재 조회 시각·기존 판단과 차단 사유·발표/정정·추천/체결/회고·모의 운영 상태·자연어 조건 초안·실험 카드를 제공한다. 현재 추적을 켜면 1분마다 완료된 최신 자료를 확인한다. 휴대폰의 127.0.0.1은 휴대폰 자신이므로 PC에 연결되지 않는다.

화면은 기존 보관 폴더에서 완료된 종목을 동적으로 찾는다. 분석이 추가돼도 서버를 수동으로 새 run에 고정할 필요가 없다. 기준 시각 이전의 자료만 선택하며 미래 수집 자료로 과거 화면을 채우지 않는다. 공개 보고서에는 개인 체결/잔고를 복사하지 않고 원시계열 재배포 권한도 별도로 검사한다.

## 기존 기능 연결 보완

- 장중 overlay는 원 분석의 차트·이벤트·근거 자료와 과거 캔들 관측본을 이어받는다.
- 이벤트 보드는 선택적 기관 자료 처리 실패와 독립적으로 보존한다. 날짜만 아는 공시를 정확한 발표시각으로 바꾸지 않는다.
- 추천 기록 후 검토 HTML을 다시 만들며 성과 DB의 연결을 포함한다.
- 캔들 비어 있음·생성 실패는 상태/품질 기록으로 남긴다.
- 과거 분석을 현재 화면에서 검토하려면 `tools/refresh_investment_review.py`로 이미 허용된 공급자에서 완료된 일봉을 현재 관측으로 추가할 수 있다. 원 분석/계획/판단 시각은 유지하고 `backdated=false`를 기록한다. 이전 관측본은 덮어쓰지 않는다. 이를 새 기업 분석이나 현재 진입 허가로 표시하지 않는다.
- 기존 파일에 수집 시각이 없으면 같은 도구의 `--reobserve-only`로 외부 조회 없이 지금 확인한 기록을 추가한다. 원래 판단·시세·만료시각은 유지하며 재관측 이전 조회에는 나타나지 않는다.

## 지속 로컬 모의매매

설치:

```powershell
powershell -NoProfile -File tools/install_investment_operations.ps1 -RepositoryRoot C:\Projects\TradingAgents -ArchiveRoot C:\TradingAgentsData\archive
```

이 설치기는 기존 분석·공개 발행 작업의 주기를 변경하지 않고, 같은 Windows 사용자에게 숨김 작업 두 개를 추가한다.

| 작업 | 동작 |
|---|---|
| `LocalAutomation-paper` | 매분 1회. 별도 로컬 모의 원장만 변경. 모델 호출·증권사 주문 전송 없음 |
| `LocalAutomation-review` | 로그인 시 실행되는 개인용 localhost 조회 서버. 종료 시 재시작 검사 |

실행기는 기존 방식대로 `fork/main`의 커밋별 복사본을 사용한다. 원 사용자 작업 폴더를 강제로 전환하지 않는다. PC가 꺼져 있거나 사용자가 로그아웃하면 이 로컬 기능은 실행되지 않는다. 시작하지 못한 과거 시점을 가짜 시세로 재생해 성과를 만들지 않는다.

모의 자료는 다음 비공개 경로를 사용한다.

- `archive/paper/kr.sqlite`, `archive/paper/us.sqlite`: 기존 점검 원장과 분리한 앞으로의 원장.
- `archive/paper/status.json`: 금액·계좌번호를 제외한 운영 상태.
- `archive/paper/*-latest-private.json`: 개인용 상세 결과. 공개 사이트에 복사하지 않음.
- 기존 local-automation 상태의 `paper/enabled.json`: `LOCAL_PAPER_ONLY`만 허용.
- 같은 상태의 `paper/HALT` 파일: 생성하면 다음 점검에 주문 대기 취소·신규 모의 주문 중지. 제거는 재개에 대한 운영자 지시가 있을 때만 수행한다.

최초 유효한 계좌와 성공한 최근 분석을 얻을 때 가상계좌를 한 번 초기화한다. 계좌 식별 범위를 같은 트랜잭션으로 고정하고 이후 실계좌 잔고로 덮어쓰지 않는다. 다른 계좌 분석의 제안은 차단한다. 기본 현금·한 종목·주문·일일 회전·일 손실 제한을 완화하지 않는다.

가격은 명시적 거래일과 시각이 있는 완료 1분봉과 호가를 조회한다. 누락·미래·잘못된 시각을 수집 시각으로 대체하지 않는다. 해외 호가의 수량을 가격으로 사용하지 않으며 응답에 다른 종목 코드가 있으면 차단한다. 국내 호가의 시각만 있는 필드는 당일 current endpoint 및 독립적으로 확인한 최근 거래일 봉과 연결한 근거를 보존한다.

새 모의 주문은 유효한 기존 실행 판단·명시적 수량/예산이 있을 때만 만든다. 원 판단/계좌/시세 시각을 각각 검증하며 새 시세만으로 과거 만료 판단을 갱신하지 않는다. 대기 주문은 이후 시각의 새 가격에서만 체결한다. 같은 실제 producer run의 제안은 재시작/재점검으로 중복 소비하지 않는다.

새 분석이 없더라도 기존 가상 보유 평가와 대기 주문 관리가 중단되지는 않는다. 상태 `VALUATION_ONLY`는 보유 평가만 진행하고 새로운 판단을 기다린다는 뜻이다. 자료가 누락되면 `BLOCKED`, 거래소 휴장일은 `MARKET_CLOSED`다. 휴장일 점검은 새로운 시세 관측이나 당일 손익 기준을 만들지 않는다. 새 거래일 일부 보유의 시세가 없으면 기준 평가액을 미정으로 보존하고 모두 확보한 뒤 정한다.

미국 모의 포트폴리오는 **원화 현금 기준 가상 포트폴리오**다. 초기 현금은 원화로 유지하고 미국 주식은 별도로 관측한 증권사 기준환율로 환산한다. 이를 실시간 외환 매매나 실제 달러 계좌 복제 수익률로 표시하지 않는다. 기준환율의 원천/종류/관측시각이 없거나 오래되면 미국 평가·체결은 차단한다.

## 자연어 조건 초안

기존 화면의 조건 입력에서 다음처럼 작성한다.

```text
거래대금 100억원 이상 그리고 전일 대비 거래량 1.5배 이상 그리고 거래정지 제외
```

지원하는 한국어/영어 명시적 수치·통화·억/조/million·퍼센트·배수·그리고/또는/아님·괄호를 기존 안전한 조건 JSON으로 변환한다. 생성된 규칙을 사람이 읽을 수 있게 보여준다. 이 화면의 초안 변환은 자동 저장·전략 동결·스캐너 설정 변경·주문을 수행하지 않는다.

```powershell
python -m tradingagents.scanner.natural_language --text "거래대금 100억원 이상 그리고 전일 대비 거래량 1.5배 이상" --market KR --output condition-draft.json
```

`강한 종목`, `충분한 거래량`처럼 수치가 없거나 미지원 지표/기간을 섞으면 완성된 규칙을 반환하지 않는다. 일부 이해한 조건만 몰래 활성화하지 않는다. 임의 Python이나 `eval`을 실행하지 않고 추가 모델 비용도 발생하지 않는다. 선택한 조건을 실제 scheduled scanner에 적용하려면 기존 `[scanner].condition` 경로를 사용하며, 이 변경은 원래의 실행 위험 심사를 대체하지 않는다.

## 실험 카드

기존 `ExperimentRegistry`를 읽기전용으로 재사용한다. 등록된 실험이 없으면 없음으로 표시하고 샘플 수익률을 만들어 넣지 않는다. 규칙/해시·데이터 버전·모델·비용·관측 기간·성과·한계를 표시하며 기록되지 않은 모델은 알 수 없음, 미래 관측이 없으면 아직 미관측이다. 읽기 요청으로 DB를 새로 만들거나 실험을 수정하지 않는다.

```powershell
python -m tradingagents.execution.experiment_cards --registry C:\TradingAgentsData\archive\experiments.sqlite --as-of <시간대-포함-현재시각> --id <실험-ID> --format html --output experiment-card.html
```

실험 등록·동결·비교 조건·실제 미래 자료 기록은 [기존 실험 안내](integrated_investment_validation_20261017_ko.md)를 따른다. 카드 UI를 추가한 것이 규칙을 자동 실험하거나 수익성을 입증했다는 뜻은 아니다.

## KIS 모의 서버 연결 및 키 준비

`KisClient`의 실계좌 조회 전용 경계는 유지한다. 별도 `KisPaperBroker`는 고정 VTS 주소, 전용 인증정보, 명시적 모의 활성화, 허용 종목/금액 정책을 요구한다. 실계좌 주소·인증정보를 폴백으로 사용하지 않는다. [모의 서버 운용·검증](kis_paper_guarded_operations_20261018_ko.md)을 따른다.

사용자는 한국투자 앱 상시 모의투자 참가를 완료했지만 2026-10-18 점검에서 전용 키·시크릿·계좌 설정은 모두 미등록이었다. 다른 기능의 개발·로컬 모의 운용은 계속 진행하되 증권사 VTS 실제 연결·주문 검증은 이 설정과 정규장 조건을 확보해야 한다.

공식 안내에 따른 준비 순서:

1. 한국투자 앱 `모의투자 로그인 → 상시 모의투자 → 주식 잔고 손익`에서 모의 주식 계좌를 확인한다. 공식 공지는 주식 모의계좌가 5로 시작한다고 안내한다.
2. PC의 [Open API 서비스 신청 페이지](https://securities.koreainvestment.com/main/customer/systemdown/RestAPIService.jsp)에 로그인해 그 모의계좌로 API를 신청한다. 일반 모의 참가 화면과 API 신청 계좌 목록은 별개다.
3. 신청 과정에서 발급되는 APP Key·APP Secret을 확보한다. 로그인 뒤 세부 버튼은 계정 화면에 따라 확인한다. [공식 서비스 이용안내](https://apiportal.koreainvestment.com/about-howto), [모의투자 API 공지](https://apiportal.koreainvestment.com/) 참조.
4. 기존 `tools/setup_kis_demo.ps1`로 로컬 보안 입력 창을 열어 등록한다. 채팅·Git·문서에 비밀값을 붙여 넣지 않는다.
5. `python -m tools.kis_paper readiness`는 값 없이 준비 상태만 확인한다. 준비가 끝난 뒤 `probe`로 모의 인증·잔고·당일 주문을 조회한다. 접속 성공과 주문/체결 검증은 별도 결과로 표시한다.

실계좌 자동 주문 활성화는 이 작업의 범위에 포함하지 않는다. 모의 주문의 접수·부분체결·전량체결·취소·미확인은 구분하며, 응답 유실 주문을 재시작 후 무조건 재전송하지 않는다. 정산 시각·비용이 확인되지 않은 누적 체결 응답으로 정산 성과를 만들어 넣지 않는다.

## 검증 및 운영 영수증

오프라인 회귀에는 정상·빈 응답·미래/누락/잘못된 시각·다른 계좌/종목·미래 자료를 새 시세로 덮는 경우·재시작/중복·손실 제어·호가 가격과 수량·부분 체결/취소 경합을 포함한다. 브라우저는 네 화면 폭에서 현재 자료 추적·모의 상태·조건 초안·실험 카드·과거 replay·잘못된 입력 초기화를 검사한다. Windows 설치기는 실제 작업 등록 없이 격리 테스트에서도 검증한다.

실제 운영 활성화 및 최종 테스트/CI/PR 결과는 이번 변경의 PR과 로컬 `archive/paper/status.json`, `local-automation/paper.log` 및 Windows 작업 상태를 기준으로 확인한다. 4~8주 미래 성과를 개발일에 채워 넣지 않는다.

2026-10-18 실제 보관 자료 점검에서는 완료된 121개 종목을 찾았다. 120개는 공급자에서 완료 일봉을 확보했고 WBD는 `VendorMalformedResponseError`로 확보하지 못해 실패 기록과 원본을 보존했다. 121개 종목의 기존 판단/계약 재관측은 외부 요청 없이 완료했다. 삼성전자와 AAPL의 실제 화면 응답에서 260개 완료 봉, 기존 판단, 가격 수준과 차단 사유, `STALE` 표시 및 `reobserved_archive` 출처를 확인했다. 당일은 휴장일이므로 로컬 모의 점검은 국내·미국 모두 `MARKET_CLOSED`이며 체결 실적을 생성하지 않았다.
