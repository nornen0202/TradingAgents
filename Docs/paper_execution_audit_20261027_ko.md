# 모의매매 진단 교정 및 호가 체결 경로 검증

검토 기준은 `bfa87e14b` (`fork/main`, 2026-10-27)이다. 제공된 외부 감사 요약을
현재 실행 코드·관련 커밋·Windows 예약 작업·운영 상태 영수증·읽기 전용 SQLite
조회에 대조했다. 모든 과거 커밋·브랜치를 전수 감사했다는 뜻은 아니다.

## 운영 증거

2026-10-27 10:33 KST의 내부 모의매매 상태는 한국 체결 0건, 거절 768건,
취소 5건이었다. `LocalAutomation-paper`는 실행 중이며 최신 소스 리비전은
위 기준 커밋이었다. 한국 30종목 중 29개는 실행자료가 준비되었지만 배분 주문은
0개였다. KIS 전략 영수증의 원본 리서치는 30개 모두 `entry_action=WAIT`,
`conditional_entry_action=NONE`이었고, 모의계좌 연결 게이트는 통과했다.
자료 준비와 매수 승인, 배분, 체결은 서로 다른 상태다.

`kis-session-validation.json`에는 한국·미국 각각 10월 19일의 KIS 모의계좌
주문 접수·체결·취소 검증 기록이 있고, 현재 두 시장 모두 `VERIFIED`였다.
이는 연결 검증의 체결이며 정상 전략 성과로 합산하지 않는다.

운영 자료 위치는 `C:/TradingAgentsData/archive/paper/` 및
`C:/Projects/TradingAgents/.runtime/local-automation/`이다. 원본 계좌번호·키·
잔고 원문은 저장소에 복사하지 않았다. 기존 원장·신호·예산·활성 설정도 초기화하지 않았다.

## 수정 내용

1. `normalize_quote`가 기존 완료 분봉 평가가격과 함께 `execution_quote`를 반환한다.
   이 객체에는 KIS의 매수·매도 호가, 실제 호가 사건 시각, 수신 시각을 따로 보존한다.
   새 실행 객체의 시계는 UTC로 정규화한다. 미국 가격은 기존 검증된 환율로
   양쪽 호가를 모두 KRW 환산한다. 환율은 평가용 기준환율이며 실제 환전 체결이 아니다.
2. `PaperBroker`는 주문 생성보다 **엄격히 나중인** 유효 호가만 사용한다.
   동일·과거·미래·누락·잘못된 시계, 역전 호가, 과도한 스프레드는 체결하지 않는다.
   매수는 ask, 매도는 bid가 지정가 안에 있을 때만 가능하다. 가상 슬리피지는
   지정가까지의 가격 여유만 소모한다. 지정가 밖의 실제 호가를 캡핑하여 체결하지 않는다.
3. 실시간 호가가 있으면 다음 완료 분봉을 기다릴 필요가 없다. 기존 분봉 전용
   입력은 기존 체결 모형을 유지한다. 계좌 평가는 계속 완료 분봉을 사용하며,
   현금·집중도·회전·손실·매도 가능 수량 검사를 통과해야 한다.
4. CLI·예약 실행·완료 리서치 전달 경로는 PENDING 주문이 있을 때 같은 원장 잠금
   아래 1초 후 한 번 더 독립 조회한다. 계좌·개장 상태·HALT·TTL을 다시 확인한다.
   무한 재시도나 TTL 갱신은 없으며, 한 번의 추가 조회 후 다음 예약 실행으로 돌아간다.
   1초는 재조회 전 대기 시간이다. API 지연까지 포함한 실행시간 상한을 뜻하지 않는다.
5. 체결 lifecycle에 `fill_basis`와 `quote_event_at`을 남긴다. 기존 주문·성과를
   소급해서 채우지 않으며 새 근거로 발생한 체결만 기록한다.

단기 주문의 매수·매도, 지정가 안/경계/밖 호가, 시계 오류, HALT, 만료, 장 마감,
계좌 변경, 호가 미갱신 및 WAIT 무주문을 검증한다. 브로커·LLM 호출은 없다.
기존 수량·손실·중복 방지·원장·시계 검사를 함께 실행한다.

조회 전용 호가를 사용한 왕복 체결 점검도 수행했다.

하위에만 보관한다. 이 결과는 로컬 체결 경로의 동작 증거이며 수익성 증거가 아니다.

## 운영 적용과 남는 조건

기존 런처는 `fork/main`의 불변 소스 스냅샷을 사용하므로 병합 이후 다음 예약
실행부터 수정본을 사용한다. 별도 워커를 중복 설치하거나 저장된 원장을 지울 필요가 없다.
확인은 `paper/status.json`의 `source_revision`, `checked_at`, 주문 수, 그리고
체결 lifecycle의 새 근거 필드를 대조한다. 미체결 재조회가 수행되면
`pending_follow_up_attempted=true`가 기록된다.

원본 리서치가 WAIT이고 배분이 없다면 체결 0은 정상적인 전략 대기다.
관측된 768개 거절과 5개 취소를 모두 이 결함 하나 때문이라고 단정하지 않는다.
그 주문들은 과거 그대로 보존한다. 최신 시세 자체를 구하지 못하거나 TTL 내
더 늦은 호가가 없으면 여전히 체결하지 않는다. 소액 한도 확대·뉴스 누락 시
자동 매수·Alpaca 추가는 이번 원인의 해결에 필요하지 않아 적용하지 않았다.
