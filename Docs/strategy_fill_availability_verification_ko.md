# 정상 전략 체결 가용 시각과 성과 이력 검증

## 재현한 결함

국내·미국 모의 broker의 실제 대사 함수를 Mock 응답으로 실행했다. BUY 체결 확인 뒤 SELL을 준비하고 전량 체결하면 왕복 1회·실현 총손익 3이었지만, 같은 BUY 누적 수량·대금을 나중에 다시 조회하면 왕복 수와 실현 총손익이 미확정으로 바뀌었다. 추가 전용 원장에 새 조회 시각이 남고 평가기가 그 최신 시각을 최초 체결 가용 시각으로 사용한 것이 원인이다. 수량·총현금흐름은 그대로였으며, 실제 증권사 체결을 새로 만든 실험은 아니다. 정상 자동 루프는 금액이 확인된 종료 주문을 재조회에서 제외하므로 매 분 모든 종료 주문에서 발생한다고 주장하지 않는다.

별도 읽기 전용 재현에서 과거 성과 3개 뒤 미래 성과 60개를 추가하면 과거 기준일의 표시 이력이 비었다. 데이터베이스에서 날짜 문자열 내림차순 60개를 먼저 고르고 기준일을 나중에 적용했기 때문이다. 서로 다른 UTC offset의 유효한 61개 기록에서도 실제 최신 시각이 문자열 정렬 때문에 제외됐다.

## 변경 계약

`summary`는 원래 ACK·broker 주문 ID·주문 조건·demo 출처·누적 수량·대금·관측 및 수집 시각을 검증한다. 원장 기록을 UTC 시각 순으로 읽고 현재 **연속된 동일 수량·대금 상태**가 최초로 가용해진 한 보고의 관측·수집 시각 쌍을 `fill_availability`로 투영한다. 최신 `observed_at`·`ingested_at`과 원장 행은 보존한다.

부분 체결에서 수량이 증가하거나 대금이 처음 확인된 경우에는 가용 시각을 다시 계산한다. 대금 확인→누락→다시 확인도 새 버전으로 취급한다. 이전 일부 수량이나 대금 미확인 보고의 시각을 나중에 확인한 전체 체결에 소급하지 않는다. 값 회귀·동시각 상충·미래/누락/잘못된 시각·원래 주문 증거 불일치는 계속 거절한다.

왕복 순서는 이전 주문의 현재 경제적 상태가 후속 주문 준비 전에 확인됐는지로 판정한다. 새 증거 필드가 아예 없는 기존 호출자는 최신 시각을 쓰는 기존 보수적 동작을 유지한다. 필드가 있는데 null·불완전·잘못된 값인 경우에는 이 fallback을 적용하지 않는다. `first_fill_observed_at`과 평가 표본의 최초 시각은 **최초 양수 누적 보고 관측시각**이며 실제 거래소 체결 발생시각은 아니다.

성과 이력의 공통 읽기 함수는 유효한 aware 시각을 해석하고 기준일 이하만 남긴 뒤 UTC 순 최신 60개를 선택해 오래된 순서로 표시한다. 시각 키를 순차 조회하고 크기 60의 heap만 유지하며 선택된 payload만 읽는다. 표시할 수 없는 날짜와 미래 행은 분석 근거에서 제외한다. 원장·주문·평가 총액을 수정하지 않는다. 주문·체결 보고 자체에 미래 기록이 있으면 전체 요약을 거절하는 기존 계약은 별개로 유지한다. 이를 미래 broker 보고 추가 전후 과거 평가가 항상 성공한다는 주장으로 확대하지 않는다.
