# 예약 판정의 명세 메모리 사용과 장중 신선도

## 확인한 비용

예약 실행의 `run_due`는 매 tick마다 archive의 모든 `run.json`을 읽고 전체 객체를 목록에 보관했다. 2026-10-22 진단 시 978개 파일의 원문 합계는 924,492,126바이트였다. JSON 객체로 확장한 메모리와 별도로, 후속 예약 판단에 필요하지 않은 보고서·모델 사용량 본문도 동시에 유지하는 구조였다. 운영에서 같은 전체 함수를 다시 실행해 메모리 부족을 재현하지는 않았다.

새 경로는 각 원문을 완전히 파싱한 직후 기존 완료/부분실패 선정기가 읽는 작은 필드만 보관한다. 원래 ID·label·상태·시각, 시장·실행 모드, 성공/실패/설정 종목 수, coverage의 완료 여부, 종목 ID·상태·analysis 경로, 실행 기준시각·checkpoint를 보존한다. 원래 디렉터리 정렬과 선정 정책은 유지하며, 검토 중 발견한 미래 완료 시각 누락은 아래와 같이 별도로 수정한다.

디스크 캐시나 오래된 힌트에 기대지 않으며, 오래된 파일도 끝까지 읽어 잘못된 JSON이 있으면 기존과 같이 attempt 생성·worker 실행 전에 실패한다. 누락된 날짜, 잘못된 타입, 비어 있지 않지만 완료 여부가 없는 coverage의 의미도 보존한다. 원래 manifest·연구 파일은 수정하지 않는다. 실제 재개 단계는 원본을 다시 읽고 계보·선정·artifact 해시·시점을 검증한다.

공통 iterator의 projection은 선택적이다. 예약 판정 외 기존 호출자는 원래 전체 manifest와 디렉터리 역순 목록을 받는다. 원래 승인·retry 한도·간격·시세 TTL·원장·작업 설정은 바뀌지 않는다.

메모리 범위는 **현재 한 manifest의 파싱 임시 객체와 N개 작은 선정용 객체**다. 전체 원문 읽기·파싱 CPU, 가장 큰 단일 manifest의 비용, archive 개수에 비례하는 작은 필드 목록은 남는다. 이 변경만으로 모든 장중 지연이 해결됐다고 주장하지 않는다.

## 미래 완료 기록의 제외

기존 `partial_target_source`는 기준 시각 이후에 완료한 기록을 제외했지만 `completed_target`에는 완료 시각의 상한 검사가 없었다. 미래에 완료했다고 기록된 manifest가 있으면 과거 시점의 예약 분석을 이미 끝난 것으로 간주할 수 있었다. 작은 필드만 보관하는 변경이 새로 만든 결함은 아니다.

완료 판정에도 예약 실행의 명시적 aware 기준 시각을 전달하고 `started_at <= finished_at <= now`를 검증한다. full·overlay와 실행 영수증이 없는 과거 형식에 같은 상한을 적용한다. 미래 자료가 과거 예약 판단을 바꾸지 않도록 검증하며, 이미 유효하게 완료한 과거 기록과 원래 한도·간격은 유지한다. 이 시간 상한은 의도된 수정이므로 모든 과거 동작을 바이트 단위로 보존했다고 주장하지 않는다.

## 검증 범위

테스트는 20개 파일에 각 1MiB의 불필요한 본문을 넣고 파싱 peak가 6MiB 미만, 반환 후 보관량이 1MiB 미만임을 확인한다. 기존 전체 본문 목록이면 최소 20MiB 문자열만 남아야 하는 사례다. 운영 924MB 원문을 다시 일괄 적재하는 검사는 수행하지 않는다.

작은 필드 투영 자체는 KR/US·full/overlay·정상/부분실패·미래/누락/잘못된 날짜·동일 timestamp·잘못된 타입에서 전체 원문과 같은 선정 결과·예외를 유지하는지 검증한다. 원본 바이트·정렬·기본 caller 반환, 오래된 깨진 JSON의 attempt 이전 실패, 캐시에 가려지지 않는 새 완료도 포함한다. 독립 경량 AST 검증의 입력 1,809개·선정 결과/예외 7,236개 일치는 투영의 동등성 증거이며, 미래 완료 상한을 추가하기 전 결과다. 새 시점 상한과 미래 기록 추가 전후의 예약 판정은 별도 검사로 검증한다. 최종 테스트 및 CI·배포 수치는 별도 검증 기록으로 확인한다.

투영과 기존 예약 경로의 두 순차 묶음은 308개·160개, 총468개를 통과했다. 미래 완료 상한을 추가한 뒤 변경 관련 6개 파일은 333개 통과·1개 제외였다. 제외한 것은 이미 통과한 대용량 메모리 사례이며 수치를 합산하지 않는다. 별도 독립 시점 경계 306개는 동일 시각 허용·1마이크로초 미래 제외·다른 offset의 동일 순간·미래 기록 추가 불변·잘못되거나 naive 기준 시각 거절을 확인했다. Ruff의 변경 코드 검사와 저장소 CI 규칙, diff 검사가 통과했고 독립 리뷰에서 추가 P1/P2는 발견하지 못했다.
