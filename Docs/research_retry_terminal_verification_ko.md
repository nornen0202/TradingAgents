# 신규 연구 성공이 없는 재시도의 종료 계약

## 운영에서 확인한 문제

미국 실행 `20261022T192108_local-scheduler-us-full`은 2026-10-22 22:12:10 KST에 `partial_failure`로 종료했다. 30종목 중 분석 파일 22개·오류 8개이며 immutable source는 `0741e528`이다. 전체 10,261.97초 중 종목 처리 후 단계는 1,420.89초였다. 전체 LLM 기록은 582회·16,078,423토큰이며, 이는 금전 비용 측정값이나 전부 불필요한 호출이었다는 뜻이 아니다.

기존 자동화는 22:15:31에 원래 재시도 4회 한도 중 세 번째 시도를 시작했다. 새 실행 `20261022T221611_local-scheduler-us-full`은 source `ee554c9b`에서 성공 22종목을 재사용하고 실패 8종목만 재연구했다. 원본 manifest·선정 증명 SHA와 재사용 `analysis.json`/`execution_contract.json` 44개 바이트 해시가 일치했다. 원래 승인 22개는 모두 WAIT/NONE·만료 없음이며 현재 시각으로 갱신되지 않았다.

재시도 8종목은 22:16:37까지 모두 동일 데이터 오류로 실패했고 개별 LLM 호출은 0회였다. DELL·ETN·BRK-B·CVX·PM·XOM은 잘못된 KIS OHLCV, GEV·RHHBY는 요구 이력 범위 부족이었다. 그런데 22:34:31 자식 프로세스의 모델 턴 완료와 22:37:35까지 이어진 모델 출력이 확인됐다. 신규 연구 성공 없이 후처리가 20분 이상 계속되는 실증이다. 진행 중인 실행을 종료하거나 잠금을 지우지는 않았다.

원인은 기존 성공 결과를 신규 결과와 합친 뒤 전체 성공 유무로 후처리 중단을 결정하는 분기였다. 재사용 22개 때문에 최초 PR #431의 전종목 실패 차단을 통과하고 뉴스·포트폴리오 모델 경로로 진입했다. 점유하는 것은 연구 lane과 모델·메모리 자원이다. 분리된 minute producer 잠금을 직접 잡았다는 근거는 없다. 23:00~23:30 제한 연구의 진입은 같은 연구 lane과 일일 재시도 우선순위에 영향을 받는다.

## 수정 범위와 보존 조건

명시적 `resume_from_run`이고 재시도 대상이 비어 있지 않으며 **이번 worker의 성공 0개·실패 있음**일 때만 후처리를 생략한다. 실패에는 기존 집계와 같이 예산으로 건너뛴 `skipped`도 포함한다. 이 판정은 재사용 결과를 합치기 전에 수행한다. 뉴스 추가 수집·실행 갱신·포트폴리오 모델·의사결정 묶음·성과 원장·소비자 호출을 시작하지 않고, 결정론적 커버리지 검증과 종료 manifest 발행을 수행한다.

전체 결과는 실제 집계대로 `partial_failure`와 30/22/8을 유지한다. 기존 성공 22개를 실패로 바꾸거나 신규 성공으로 집계하지 않는다. 새로운 종료 사유와 신규·재사용 수치를 구분하며, 원본 계보·파일·승인 시각·원본 사용량과 이번 실행 사용량을 보존한다. 엄격한 완료 판정은 계속 실패하므로 정상 완료 기준선·원래 주문 승인으로 승격되지 않는다. 다음 재개에서도 같은 검증된 원본 계보를 이어갈 수 있어야 한다.

모든 종목이 처음부터 실패한 기존 경로는 유지한다. `finalize_from_run`처럼 새 연구 없이 이미 끝난 종목 처리를 정리하는 경로와, 재시도에서 신규 성공이 하나라도 있는 경우는 기존 후처리를 수행한다. 재시도 예산·간격·선정 정책·원래 승인·원장·실계좌 설정은 변경하지 않는다. 현재 실행은 immutable source에서 그대로 마무리되며 새 코드는 이후 정상 실행에 적용된다.

두 표적 파일 `tests/scheduled/test_failed_research_terminal.py`와 `tests/test_research_recovery.py`의 오프라인 검사 126개가 13.16초에 통과했고 Ruff·diff 검사도 통과했다. 실제 loader/copy로 22개 재사용·8개 실패, 순차/병렬 worker, 건너뜀 전용 결과, 원본 파일·시각 불변, 재사용 440회와 이번 실패 16회 사용량 분리, 후속 중첩 재개, 신규 성공 및 순수 finalization을 검증했다. 독립 정적 리뷰와 실제 guard AST 경계 검증에서 추가 P1/P2는 발견하지 못했다. 정확한 head CI·병합·배포는 별도 확인 대상이다. 구현 또는 Mock 결과를 현재 실행의 중단·복구·승인·실제 체결 성공으로 해석하지 않는다.
