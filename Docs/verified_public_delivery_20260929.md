# 2026-09-29 최신 자료 전달 보강

## 재현한 잔여 문제

9월 29일 직접 HTTP 요청에서는 11:58 생성본을 받았지만 웹 조회 도구는 같은 mutable URL에서 전날 14:44 생성본을 반환했다. 커밋 SHA 고정 URL에서는 당일 본문을 확인했다. 정확한 내부 캐시 계층은 확정하지 않는다. Pages Markdown의 MIME 호환 오류와 별도 대화의 DisabledError도 있었으며, 공개 URL의 존재와 도구의 사용 가능성은 별개다.

## 적용 범위

- 기존 Markdown과 함께 일반 텍스트 `latest.txt`, 구조화 `latest.json`을 제공하고 여섯 파일의 길이·SHA-256을 manifest로 검증하여 동일 커밋으로 미러링한다. 새 개인정보 필드는 추가하지 않는다.
- 새 실행마다 무작위 request_id와 no-cache 헤더로 GitHub public-context ref를 직접 조회한다. 모든 파일은 동일 SHA에 고정한다. 수집 후 ref를 다시 조회하여 변경됐으면 한 번 다시 수집하며 계속 바뀌면 실패한다.
- `python -m tradingagents.work verify-public --surface kr` 또는 `us`는 읽기 전용이다. 개인정보·인증자료·로컬 원본을 웹에 전송하지 않는다. 인터넷에서 받은 공개 원문만 검증한다.
- 파일 길이·해시·시장·생성시각·JSON/텍스트의 정확한 일치, 계좌·시세 시각, 계좌 상태·보유 전수·수량·현금/평가액을 검사한다.
- 현재 개인화 입력의 보수적 신선도 예산: 문서·계좌·시세 각각 30분 미만, 원분석 완료 36시간 미만, 미래/무시간대 시각 금지, 행 유효기간 미경과. 휴일 자료의 참고 가치는 부정하지 않으나 이를 현재 실행 입력으로 승격하지 않는다. 이 예산은 사용자 손실감내도나 주문한도가 아니다.
- 성공은 VERIFIED_CURRENT_INPUT이며 주문 승인이 아니다. 데이터 불충족은 REFERENCE_ONLY, 접근·무결성 실패는 UNVERIFIED다. 실패 시 종료코드 2이고 personalized_input/context_text는 반환하지 않는다. 이전 성공값을 재사용하지 않는다.
- 로컬 Work의 구조화 보고서 publish는 READY_NOW/WAIT_FOR_TRIGGER에 대해 현재 VALID 계좌 관측 30분 미만을 강제한다. 기존 시세·행 유효시간·원본해시 검증도 유지한다. 실패 시 보고서 게시·ACK가 진행되지 않는다. 분석 시점 thesis는 별도 참고로 보존한다.
- 국내·미국 v6 프롬프트는 고정 latest 대신 nonce 발견 → SHA 고정 → 바이트·시각 검증을 요구한다. 실행도구가 없으면 기계검증 미실시를 명시하고 현재 개인화 수량은 보류한다. 모바일 5열과 추가입금 0원+양수 4개 시나리오는 유지한다.

## 실제 클라우드 시험 후 추가 보완: v7

12:26 KST 국내·미국 실제 ChatGPT 대화 모두 GitHub ref API를 웹 도구로 읽지 못했다. 일반 HTTPS와 커밋 고정 raw 텍스트는 읽혔다. v6의 API 선행조건만으로는 클라우드 입력 수집이 정상화되지 않아 API 없이 공개 링크를 발견할 일반 텍스트 discovery.txt를 추가했다.

데이터 커밋을 만든 뒤 해당 SHA와 manifest 해시/길이, 시장별 고정 URL만 든 안내문 커밋을 만들고 마지막에 ref를 한 번만 전진시킨다. 두 단계 사이 실패 시 공개 ref는 그대로다. 계좌 값은 안내문에 넣지 않는다. snapshot_commit은 데이터 커밋이며 최신 HEAD 자체와 다르다.

안내문도 mutable URL이므로 최신 HEAD의 증명으로 간주하지 않는다. v7은 nonce 재조회·30분 시각·동일 SHA·파일 해시·원자료 시각 검사를 유지하며 최신 HEAD 확인 여부를 따로 보고한다. 기계검증이 없으면 PASS·현재 개인화 수량을 보류한다. CLI는 그대로 직접 API로 HEAD를 확인하므로 강한 검증 경로는 약화하지 않는다. 이는 공개 자료의 호환 형식 제공이지 인증·안전 제한 우회가 아니다.
