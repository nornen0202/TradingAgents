# 장중 연구 원본의 저장 중복과 보존 검증

기준: 2026-10-23 KST. 저장 구조의 개선은 연구 승인이나 체결을 대신하지 않는다. 원래 분석 시각, 계좌 소유권, 원장, 주문 한도와 120초 신선도 기준을 유지하며 실계좌 주문과 실제 투자 자동 전환은 비활성이다.

## 실제 장애와 원본 증거

PR442 배포 뒤 C: 여유 공간이 원래 4GiB 보호 기준 아래로 내려가 `LocalStorageHeadroomError`가 반복됐다. 기존 300초 대기와 연속 실패 최대 3회는 변경하지 않았다. 00:56 및 01:18에는 기존 예약 재시도가 성공해 실패 횟수가 정상 초기화됐지만 이후 다시 실패했다. 관측 시점의 디스크 여유 공간을 실패 순간의 측정값으로 간주하지 않는다.

01:19·01:25·01:30의 연속 실패로 미국 거래일 10월22일의 시세 갱신 재시도 3회가 소진됐다. `storage-refresh-budget-exhausted-20261023.json`은 마지막 영수증 원문 SHA-256 `86abcd174fad6409f0cc84192a358b82512e112f84dbe20ef3a3a5c6563e5510`을 보존한다. 당일 횟수를 초기화하거나 강제 실행하지 않는다. 다음 정규 overlay는 별도 기존 예산을 따르며, 제한 재분석은 STARTED 기록 전에 신선한 자료와 대상 선정 조건을 먼저 통과해야 한다. 공간 회복만으로 즉시 분 단위 검증을 다시 시작할 수 있다고 주장하지 않는다.

첫 고정창 `open-session-442-us-20261023T0020.json`은 00:19:46.572115~00:34:48.003168, 901.4초 후 실패했다. 356개 반복 관측에서 새 공동 자료 6개와 전체 만료 170개 샘플을 확인했다. 이후 압축 작업을 마친 다음 별도 고정창 `open-session-442-us-poststorage-20261023T0104.json`을 실행했다. 이 창 역시 01:03:26.075696~01:18:26.832715, 900.8초 후 실패했다. 358개 반복 관측에서 새 공동 자료 4개, 전체 만료 224개 샘플이었다. 두 창 모두 부분 만료와 버전·소비자 시계·신선도 미검증 샘플은 0개다. 반복 샘플을 독립 생산 실패 횟수로 세지 않는다.

후속 창 원본 SHA-256은 `9bb46b6114dd9804952f3df5373a4c925e449f52cd927a2f70877aba32518159`다. 원본과 실패 요약은 `.runtime/local-automation/live-verification/`에 별도로 보존한다. 중간 시점의 만료 0개를 최종 성공으로 보고하지 않는다.

## 원본을 유지한 한시적 공간 회복

종료한 과거 실행의 검토된 파일 3,982개에 NTFS 압축을 적용했다. 같은 독점 파일 핸들에서 압축 전후 내용 해시, 크기, 원래 수정 시각, 파일 ID와 소유자·ACL을 확인했고, 핸들을 닫은 뒤 독립 재검사도 통과했다. 원본 파일을 삭제·이동하거나 내용을 수정하지 않았다.

총 논리 크기 1,503,467,693바이트의 실제 할당량은 1,511,784,448에서 848,777,216바이트로 줄었다. 회수한 할당량은 663,007,232바이트, 약 632MiB다. 이는 해당 파일의 측정 결과이며 C: 전체 여유 공간 변화를 모두 설명하지 않는다. 작은 compressed-file-size 수치와 실제 할당량도 별도로 기록했다.

독립 원본:

- `storage-compression-postclose-audit-20261023.json`: 첫 735개 파일과 57개 manifest, 문제 0개. SHA-256 `423608e8d9e5cd54e903b1ac647347c2dde873815a78a3f9360be2137a5fa4d0`.
- `storage-compression-postclose-audit-c-20261023.json`: 추가 3,247개 파일과 61개 manifest, 문제 0개. SHA-256 `693c2e45b4c5607852940de7aba5f0b41deafc94cb39e7a36b7bcd789bba59a4`.

이 조치 이후에도 저장 공간 부족은 재발했다. 기존 유지보수의 전체 삭제 기능을 실행하거나 다른 앱 작업을 종료하지 않았다.

## 분 단위 갱신에서 확인한 저장 중복

실제 미국 경량 갱신 `20261023T005817_local-freshness-us-overlay`와 `005916`은 각각 698개 파일이 모두 압축돼 있었지만 약 39.15MB의 논리 크기와 20.975MB의 할당량을 차지했다. 압축 속성 누락이나 `copy2`의 비압축 속성 전파 가설은 작은 Windows 실험에서 재현되지 않았다.

매번 복사하는 30종목의 그래프 로그는 약 8.63MB, 최종 연구 상태는 5.79MB, 보고서는 2.81MB, 차트 자료는 3.03MB다. AAPL의 네 종류 원문은 이전 실행과 해시가 같았다. HTML은 해당 실행에 0개이고 `skip_site_build=True`이므로 이 경량 갱신의 증가를 HTML 재생성 탓으로 설명하지 않는다.

반면 `analysis.json`에는 새 관측이 추가되고, 실행 계획과 청산 자료는 현재 관측으로 갱신된다. 약 5.30MB의 portfolio 자료 역시 현재 계좌를 계산한 결과다. 이런 파일을 이전 실행과 하드링크하거나 전체 재사용하면 변경 격리 또는 현재 계좌 평가가 훼손된다.

측정 근거는 `storage-new-overlay-allocation-audit-20261023-20261023T010613057971.json`, SHA-256 `be8e69be53d4265a895ba2055eda3d881b270e1ef919de4df12abbd9d35e5999`다. OS 전체 공간 감소의 앱별 기여도는 확인하지 않았다. 프로세스 I/O 카운터에는 파일 이외의 통신도 포함되므로 이를 디스크 증가 원인으로 확정하지 않는다.

## 변경의 보존 계약

경량 갱신에서 변하지 않는 `report_markdown`, `final_state_json`, `graph_log_json`만 `archive/research-snapshots`에 내용 해시로 식별해 한 번 보존한다. 원래 source manifest와 분석 시각을 입증하는 analysis 원문도 함께 보존한다. 현재 run의 행은 검증 가능한 참조를 가지며 다음 경량 갱신은 같은 원본을 사용한다. 일반 bootstrap은 필요한 원문을 해당 run의 로컬 파일로 복원한다.

읽을 때 원문 해시·크기·원래 manifest의 종목·시장·날짜·시작/완료 시각·소유 행·파일 경로를 검증한다. 현재 분석의 종목과 원래 날짜·시각도 참조와 일치해야 한다. 잘못된 날짜, 미래·역전 시각, 다른 종목·시장·분석의 참조, 손상된 원문과 경계 밖 경로는 거절한다. LLM을 비활성화해도 먼저 연구 문맥을 읽는 semantic judge와 사이트 생성 경로에 같은 검증을 적용한다.

원본 run은 기존 보존 기간이 지나면 삭제될 수 있다. 따라서 이전 run의 경로를 단순히 가리키지 않고, 별도 snapshot에 검증 근거 자체를 보존한다. 이 변경에는 snapshot 자동 삭제 기능이 없다. 저장 수명·회수 정책은 후속 검증 과제이며 무한한 공간 절감이나 저장 문제 전체 해결을 주장하지 않는다.

공유 원문은 최초 게시만 허용하고 기존 객체를 덮어쓰지 않는다. 프로세스 간 잠금과 완성된 임시 파일의 원자적 게시를 사용한다. 설정된 archive 루트는 실제 경로로 고정하되 그 아래의 경로 이탈과 reparse 참조는 거절한다. 분석·계약·주문·차트·현재 계좌 자료는 로컬로 유지한다. 전체 연구와 실패 종목 재개의 기존 엄격한 계보 검증을 완화하지 않는다.

## 검증과 운영 판정

외부 API 없는 최종 관련 8개 파일 검사에서 259개가 통과했고, Windows 파일 symlink 권한에 따른 2개는 제외됐다. 실제 디렉터리 junction과 reparse 속성 Mock 검사는 통과했다. 원본 run 삭제 뒤의 사이트 읽기·연속 overlay·일반 로컬 복원, LLM 비활성 경로, 잘못된 종목·시장·날짜·시각·해시, 동시 최초 게시와 기존 객체 불변을 확인했다. Ruff·diff 검사와 독립 검토의 7개 작은 사례도 통과했다. 독립 검토에서 발견한 다른 분석의 참조 혼합과 publication lock의 reparse 경계는 수정 후 다시 검증했다.

실제 `20261023T011820_local-freshness-us-overlay`의 AAPL manifest와 파일을 임시 archive에 복제한 6개 검사도 통과했다. 세 대상 원문은 596,547바이트였고, 첫 snapshot은 전체 manifest·분석 검증 근거를 포함해 1,638,805바이트였다. 다음 overlay에서 새 snapshot 저장량은 0바이트였다. 원래 run을 제거한 뒤 사이트, LLM 비활성 semantic 조회, 연속 참조와 일반 로컬 복원을 확인했다. 이 수치는 한 종목의 임시 복제 실험이며 운영 NTFS 할당량이나 TTL 개선 측정이 아니다. 증거 `research-reference-production-shape-20261023.json`의 SHA-256은 `e5da84ce7de0d043d396e9693186f40391536423b8d1a9f2e4f1591f20ff217c`다. 최종 정확한 head CI, 병합·배포와 운영 결과는 별도로 확인한다.

운영 경로 이동의 온라인 준비 복사는 아직 일관된 snapshot이나 이전 완료 증거가 아니다. [Microsoft Robocopy 문서](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy)의 데이터·속성·시각 복사 기능을 사용하되 이동·삭제 옵션은 사용하지 않는다. SQLite와 sidecar는 쓰기 중인 일반 파일 복사만으로 완료 판정하지 않는다. 최종 전환은 생산자·조회자 입장 차단, DB 일관성, 원본 해시·시각·경계와 원래 승인 검증이 필요하다.

새 버전의 장중 완료 기준은 최소 600초, 새 공동 완료 자료 3개 이상, 현재 revision, 전체·부분 만료 0개다. 저장량 감소나 단위 검사 통과로 이 기준을 대체하지 않는다. 2026-10-23 01:30:31 KST 읽기 전용 원장 감사에서 정상 KR/US 전략 시도·주문·체결은 모두 0이었다. 정상 전략 BUY·SELL, 국내 별도 왕복, 실제 비용·정산과 반복 표본은 계속 미충족이며 실투자 판정은 `NOT_READY`다.
