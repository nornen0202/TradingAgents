# 정상 전략 무체결 재검토와 완료 기준

2026-10-23 16:06 KST의 실제 원장과 실행 코드 기준이다. 이 문서는 기존 실패 기록을 대체하지 않는다. 코드 개선, 정상 연구 완료, 주문, 체결, 수익은 각각 다른 결과다. 아직 정상 전략 체결과 수익성을 달성하지 못했다.

## 왜 장시간 작업에도 목표를 달성하지 못했나

첫째, 성공 지표의 우선순위가 잘못됐다. 테스트·PR·배포가 많이 완료됐지만 사용자의 목표는 **정상 전략의 증권사 체결과 검증된 성과**였다. 단위 검사에서 만든 승인 fixture는 실제 연구가 투자 가능한 결론을 내렸다는 증거가 아니다. 정상 연구와 실행이 연결되는 운영 검증을 더 일찍 최우선으로 삼았어야 했다.

둘째, 복구가 매번 다음 단계에서 막혔다. 최초의 전체 자료 실패를 고친 뒤에도 일부 종목의 시계열 오류, 장기 지표 입력 범위, 재개 계보 손상, 저장공간 부족이 순차적으로 드러났다. 생산이 멈추면 120초 자료가 만료되고, 신선한 자료를 요구하는 한정 재분석도 시작하지 못했다. 오래된 WAIT 연구를 복제하는 overlay는 새 매수 승인을 만들지 않는다.

셋째, 관측 가능성이 부족했다. 주문 계획기의 `allocation_diagnostics`에는 탈락 이유가 있지만 사용자 API에서 빠졌다. `EXECUTION_OBSERVATIONS_AVAILABLE`도 화면 투영의 허용 상태에서 빠져 차단처럼 보였다. 시세 갱신의 당일 재시도 소진은 일반적인 신호 대기와 구별되지 않았다. 이 상태에서는 기다려도 해결되지 않을 장애와 정상적인 관망을 구분하기 어렵다.

넷째, 표시와 실제 실행의 계약이 달랐다. 신선한 데이터의 `execution_ready`와 `IMMEDIATE`는 매수 승인이 아니지만 포트폴리오 참고 의견이 실행 엔진의 명시적인 NONE보다 우선해 화면에서 BUY_NOW로 표현될 수 있었다. 주문 계획기는 원래 승인을 다시 검증해 주문을 막지만, 사용자는 준비된 전략이 왜 거래되지 않는지 알 수 없었다.

다섯째, 성과 평가는 아직 실제 비용과 정산을 연결하지 못했다. 비용 가정을 넣은 손익 민감도는 실제 순수익이 아니다. 거래 표본도 없는 상태에서 모델 품질이나 수익성을 판정할 수 없다. 이를 추가 기능의 완료나 단회 검증 거래로 대신할 수 없다.

## 이번 감사에서 수정한 결함

1. **실행 NONE의 표시 승격**: 실행 문맥에 명시한 `decision_now`와 `decision_if_triggered`를 포트폴리오 참고 의견보다 우선한다. NONE→BUY_NOW, 조건부→즉시 매수 반례를 수정 전 재현했다. 원래 즉시 매수·위험 축소·청산은 그대로 표시한다.
2. **자료와 행동의 혼동**: 기존 소비자 호환을 위해 `execution_ready`의 자료 계약은 유지한다. 새 `data_ready`, `action_ready`, `action_status`, `action_ready_rows`로 구분한다. `ACTION_SIGNAL_PRESENT`도 증권사 주문 허가가 아니며 원본 연구·소유권·현재 계좌·호가·한도 검사를 계속 거친다. 보고서·모바일·AI 투영과 Work 지침에도 구분을 전달한다. 자료가 만료되면 새 행동 필드도 차단한다.
3. **주문 계획 진단 누락**: 허용된 이유 코드·집계만 사용자 API와 화면에 전달한다. 경로·개인 계좌·증권사 주문번호·임의 오류 문자열은 전달하지 않는다. 신선한 자료 수, 계획 검사 통과 후보, 정상 전략 소유분, 주문·체결 표본을 각각 표시한다.
4. **재시도 소진 은폐**: 기존 갱신 영수증을 읽기만 하여 거래소 현지 날짜, 시작·완료 시각, 실패 횟수를 대조한다. 휴장 중에도 당일 한도 소진을 보여주고 이전 거래일 실패와 구분한다. 재시도 횟수·300초 대기·원래 원장은 변경하지 않는다. 완료 1회는 연속 신선도 통과라고 표시하지 않는다.
5. **표시용 시각 정상화**: 미래 시각을 나이 0으로 바꾸거나 시각대 없는 값에 현재 시각대를 붙이지 않는다. 정확히 만료 경계에 도달한 자료는 실시간 준비 상태가 아니다. 기존 주문 직전의 더 엄격한 검증도 유지한다.
6. **시작 가이드 충돌**: 과거의 실투자 우선 안내를 현재 모의 검증→비용 성과→별도 실투자 승인 순서와 명확히 구분한다.
7. **화면 검사 사각지대**: 이번 진단 추가의 첫 브라우저 실행에서 병렬 HTTP 요청의 지연 import가 교착 오류를 냈지만 이후 요청이 성공해 기존 화면 검사는 PASS를 반환했다. 진단의 생산 모듈 의존성을 제거하고 기존 재시도 상수만 가벼운 모듈로 공유했다. 브라우저 검사는 이제 서버의 미처리 예외도 실패로 처리한다. 화면에 실제 무행동 이유·재시도 소진·저장공간 원인이 나타나는지 확인한다.

최종 관련 오프라인 149개 검사, 360/390/430/1440 화면 검사와 Ruff·diff 검사가 통과했다. 390/1440 화면도 직접 확인했다. 앞선 더 넓은 회귀 352개는 그 시점 소스의 증거이며 최종 149개와 합산하지 않는다. 최종 head 전체 CI와 배포 후 실제 생산·화면 검증은 별도 기록해야 한다. 이 테스트 수가 실제 체결이나 수익성의 증거는 아니다.

## 수익 검증으로 가는 운영 순서

1. 기존 정상 연구에서 필수 자료·출처·종목 커버리지와 원래 정형 판단을 확인한다. WAIT는 정상적인 관망일 수 있다. 자료 실패로 생긴 WAIT와 투자 판단에 따른 WAIT를 근거별로 구별한다. 매수를 만들기 위한 재호출·순위 변경은 하지 않는다.
2. 실제 승인된 종목이 생기면 같은 연구·전략 버전으로 신선한 관측, 원래 허용 종목·한도, 모의계좌 소유권을 검증한다. 제출·ACK·부분/전체 체결·취소·잔고 대사를 연결한다. SELL은 해당 전략이 실제 소유한 수량과 원래 청산 근거로 수행한다.
3. 원래 규칙을 동결한 정상 전략 표본을 수집한다. 표본을 본 뒤 좋은 구간만 선택하거나 실패 거래를 제외하지 않는다. 기준 전략·동일 자본·현금흐름·투자 가능 종목·비용 조건을 맞춰 비교한다.
4. 실제 수수료·세금·FX·정산·정정의 귀속과 매수·매도 양쪽 비용 범위가 증명된 뒤 순손익을 계산한다. 비용 지원이 불확실한 API를 실전 호스트로 우회하거나 계좌 일별 총비용을 임의 배분하지 않는다.
5. 수익성 판단 전 별도 기간 검증과 시장 국면별 결과, 낙폭·슬리피지·회전율·모델 비용, 단순 기준 전략 대비 초과성과와 불확실성을 제시한다. 표본 수·관측기간·손실 중단 기준은 평가 전에 동결해야 한다. 특정 횟수의 체결만으로 수익성 통과를 선언하지 않는다.
6. 위 근거가 충분해진 뒤에만 실제 계좌에서의 제한된 검증안을 사용자에게 제시한다. 실투자 주문 활성화는 별도 결정이며 손실 없이 수익이 발생한다는 보장은 없다. 현재 실계좌 주문 비활성을 유지한다.

공식 [Alpaca 모의 환경](https://docs.alpaca.markets/us/docs/paper-trading)은 실제 거래의 시장 충격·대기열·지연 슬리피지·일부 비용과 차이가 있음을 설명한다. 이는 비교 설계의 참고이며 KIS 모의의 정확한 체결 규칙을 대신하지 않는다. [LEAN 운영 대사](https://www.quantconnect.com/docs/v2/writing-algorithms/live-trading/reconciliation)와 [Freqtrade 미래 참조 검사](https://www.freqtrade.io/en/stable/lookahead-analysis/)를 각각 증권사 상태 대조, 지표·진입/청산의 시간 누수 검증에 참고한다. 외부 프로젝트의 수익률을 이 전략의 성과로 인용하지 않는다.

## 재발 방지의 완료 조건

PR454 추가 리뷰에서 조건부 `REDUCE/EXIT`가 행동 없음으로 표시되는 오류와 연구 `entry_action=NONE/EXIT` 한 행이 전체 주문 차단 사유 표시를 제거하는 오류를 재현해 수정했다. 조건부 위험 축소는 대기 상태로 보존하며 즉시 주문 권한을 부여하지 않는다. 연구 진입 조건의 더 좁은 허용값은 그대로 검증한다. 원래 결정값 보존과 전체 정형 entry enum, 잘못된 조건값 거절을 오프라인 회귀로 확인한다.

후속 리뷰에서는 Work packet이 자료 `IMMEDIATE`만으로 `READY_NOW`를 만드는 하류 단절도 17개 실패 사례로 확인했다. 이제 raw payload를 생략하기 전에 엔진의 원래 즉시·조건부 판단을 명시적 실행 계약으로 전달한다. NONE는 연구 참고, 조건부 매수·축소·청산은 조건 대기로 구별한다. 이미 만료·차단된 실행은 승격하지 않고 보고서 검증도 원래 실행 행동을 반대 방향으로 바꾸거나 즉시 행동으로 승격하면 거절한다. 분석 thesis는 별도 유지한다. 이 수정과 Work 전체 관련 회귀 303개, 화면 4종이 통과했으며 앞선 검사 수와 합산하지 않는다.

시세 생산의 STARTED 영수증만으로 실제 프로세스가 살아 있다고 표시하지 않는다. 마지막 허용 시도의 완료 기록이 없으면 현재 실행 여부·완료 미확인으로 남기며 원래 한도는 바꾸지 않는다. 화면 검사 서버의 예외 포착은 지원 최저 Python 3.10에서도 동작하는 API로 고쳤고 원래 오류 포착과 정상 연결 종료 구분을 별도 검증했다.

관측 순서는 **자료→정상 연구→원래 승인→실행자료→계좌·한도→제출→체결→비용·정산→검증 성과**다. 첫 미충족 단계와 다음에 필요한 증거를 먼저 보고한다. CI 통과 개수나 PR 수를 운영 완료의 대리 지표로 쓰지 않는다. 현재 남은 미충족 항목은 실제 정상 BUY·SELL, 연속 장중 소비, 비용·정산·정정 귀속, 반복·별도 기간 성과다. 따라서 이 감사와 수정 후에도 전체 목표를 완료 또는 실투자 준비 완료라고 표시하지 않는다.

후속 한정 검토는 [재무 통화 전달 근거](fundamental_currency_evidence_20261026_ko.md)에 별도로 기록했다. 필수 요청 COMPLETE와 통화·단위·공시시점 확인, 원래 투자 판단은 구분하며 이전 실패와 판단을 소급 수정하지 않는다.

새 국내 정상 연구의 네 후발상장 종목에 대해서는 [최초상장·전체 이력 경계 검증](kr_listing_start_contract_verification_20261026_ko.md)을 보완했다. 자료 검증 목록은 주문 허용목록이 아니며, 공식 최초상장 이전만 별도 검증 경계로 구분한다. 상장 후 누락 세션·원래 지표 최소 관측·실제 공급자 및 조정 기준은 계속 검증한다.

과거 추천 글자가 캔들을 가리는 후속 화면 문제와 원문·정밀 시각 확인 방법은 [과거 추천 차트 안내](historical_signal_chart_readability_20261026_ko.md)에 기록했다. 과거 추천과 현재 승인·체결을 구분하며 실제 체결 표시는 그대로 유지한다.
