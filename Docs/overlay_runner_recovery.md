# 장중 갱신 실행기 복구: 제한된 사전검사

2026-10-02 KST 조사에서 US 장중 작업은 일반 Windows 실행기를 기다리는 반면,
별도 `tradingagents-pages` 실행기는 기존 게시 작업을 완료한 사실을 확인했다.
이 사실만으로 Pages 실행기를 장중 데이터 생산에 투입해도 안전하다는 뜻은 아니다.

## 검사 범위

`.github/scripts/overlay_runner_preflight.py --market all`은 기존에 설정된 환경만 사용한다.

- Windows 여부, 명시된 절대 archive 경로의 존재 및 목록 읽기 가능 여부
- archive의 새 고유 임시 하위 디렉터리에 상수 시험 바이트 쓰기, 원자적 교체,
  별도 프로세스 간 배타적 파일 잠금, 정확한 시험 파일과 디렉터리만 삭제
- 기존 KIS 설정 및 US 시세 공급자 설정의 존재 여부를 boolean으로만 확인
- 지정된 Codex 실행 파일 또는 PATH 검색 결과와 `codex login status` 종료 코드
  확인(10초 제한, 표준출력·오류출력 폐기)

계좌 파일·토큰 저장소를 열거나, 공급자·증권사에 요청하거나, 로그인을 시작하거나,
모델을 호출하지 않는다. 출력 JSON에는 설정값, 로컬 경로, 계좌·고객 식별자가 없다.
Windows·archive 기본 검사가 누락·실패하면 종료 코드 1이다. 공급자 설정·Codex 상태는
별도 진단 항목이며 기본 검사 성공을 차단하지 않는다. 성공도 주문 승인이나 생산
실행기 전환 승인이 아니므로 `ready_for_live_routing`은 항상 false다.

## 이번 복구 변경

- 실행기 JSON 저장을 임시 형제 파일·flush/fsync·원자적 교체로 변경했다.
  토큰 갱신은 같은 로컬 캐시 경로를 사용하는 프로세스·스레드가 잠근 뒤
  캐시를 재조회한다. 거부된 토큰은 재사용하지 않고 저장 실패는 중단한다.
- 완료한 run 원문을 보존하고, 짧은 프로세스 잠금 안에서 `latest-run.json`을
  시작시각·run 식별자 순으로 비교해 갱신한다. 늦게 끝난 이전 run이 최신
  인덱스를 되돌리지 않는다. 이 인덱스는 최신 시세나 성공을 보증하지 않으며
  full/overlay·시장별 원문을 합치지 않는다.
- `overlay_only`의 기본 실행 요약은 모델 호출을 생략한다. 사용자가 모델을
  명시한 경우와 정규 분석의 모델 선택은 변경하지 않았다.
- US VWAP는 한 응답 안의 거래금액·거래량 쌍 또는 검증된 당일 정규장 연속
  분봉만 사용한다. 전일·장외 봉, 누락 구간, 충돌 중복을 제외하며 KIS의
  `evol/eamt`를 인식한다. 고저 범위 밖 값은 실행 입력으로 승격하지 않는다.
- 거래정지 필드 부재는 미확인으로 유지한다. 거래소 달력의 변경된 API,
  UTC-aware 일정, 초 단위 시각을 처리하고 달력 실패 시 실행 게이트를 닫는다.
- 보조 실행기 사전검사는 trusted main 코드만 실행하며 계좌·공급자 요청 없이
  실제 archive 읽기/고유 시험 파일 쓰기/교체/잠금 가능 여부를 확인한다.
  설정 진단은 이 검사 작업에 주어진 환경만 의미하며 실제 공급자 인증 검증이 아니다.
- US/KR 장중 생산 작업은 작업별 checkout·가상환경·임시 site를 격리하고 같은 시장
  생산자끼리만 직렬화한다. `TRADINGAGENTS_OVERLAY_RUNNER_LABELS`를 명시적으로
  설정했을 때만 `overlay_only`에 전용 실행기를 사용한다. 미설정 또는 선택적
  재분석은 기존 Windows 경로를 유지하며 Pages 실행기로 자동 우회하지 않는다.
- 검증할 결과는 현재 작업의 고유 라벨로 특정한다. 공유 `latest-run.json`에
  다른 시장·다른 작업이 올라왔다는 이유로 그 결과를 대신 검증하지 않는다.
- 실패 원문·인증정보를 추가 노출하지 않고 허용목록 오류범주·예외종류·재시도
  가능성만 부모 로그에 기록한다. 이전 결과나 모르는 예외는 미확인으로 남긴다.
- 공개 계좌의 마지막 `VALID` 선택은 보존하되 `latest_attempt`로 최신 조회의
  자금제약·실패·생략·미게시 상태와 실제 관측시각을 구분한다. 원시 오류와
  식별자를 공개하지 않으며 이 메타데이터로 이전 계좌의 시각을 갱신하지 않는다.
- 원자 저장은 기존 파일 모드와 무관하게 POSIX 소유자 전용 0600으로 제한한다.
  공용 JSON 저장 함수의 과도한 읽기 권한을 지적한 CodeQL 경고를 수정한 것이다.
  Windows의 실제 접근 제어는 기존 호스트 ACL로 관리된다.

## 운영 활성화 기준

전용 실행기 라우팅을 활성화하려면 동일한 공개 소스 버전, 기존 archive 접근,
동일 로컬 토큰 캐시의 프로세스 잠금 범위, 공급자 요청 한도, 메모리·디스크 여유를
확인해야 한다. 이전 코드의 분석/overlay 작업이 끝나기 전에는 새 병렬 생산자를
추가하지 않는다. 실행기 라벨 변수는 기존에 구성된 실행기를 선택할 뿐 새 실행기를
설치하거나 호스트 접근 권한을 부여하지 않는다. 별도 권한이나 설정이 필요한 경우
임의로 credentials·세션·인증 파일을 옮겨 해결하지 않는다.

## 전환 전에 남는 조건

1. 현재 Windows 메모리·디스크 여유는 기존 `windows_resource_guard.py`로 별도 검사한다.
2. 작업별 checkout·가상환경·임시 site를 격리한다. 같은 작업 디렉터리의 pip 설치와
   cleanup을 병행하지 않는다.
3. 전역 포인터는 별도 잠금·비교로 보호하지만 모든 동시 생산자가 새 코드를
   사용해야 한다. 입력 시장·시세·계좌·유효기간 검사는 계속 별도로 필요하다.
   임시 시험 파일의 잠금 성공은 실제 생산자가 잠금을 준수한다는 증거가 아니다.
4. KIS 잠금은 같은 로컬 캐시 경로를 공유할 때만 유효하다. 다른 Windows 사용자나
   다른 호스트의 캐시는 조정하지 않는다. 같은 계정의 요청 제한을 새 실행기를
   추가했다고 별도 한도로 취급하지 않는다.
5. 명시적으로 요청한 실행 요약 모델 호출은 여전히 시간이 걸릴 수 있다.
   모델 생략은 시세 공급자 권한이나 계좌 신선도를 보장하지 않는다.
6. 수정 전 코드로 실행 중인 작업은 새 잠금·원자 쓰기 계약을 따르지 않는다.
   살아 있는 분석 작업을 이 검사로 종료하거나 다른 실행기로 옮기지 않는다.

이 사전검사는 실행기 설치, 예약 작업 추가, 라벨 변경, 생산 작업 자동 전환을 하지 않는다.
기존 Pages 성공 로그로 archive 읽기 접근은 확인됐지만, 실제 공급자 권한·시세 지연·
원분석과 보유 전수 정합성은 이후 정상 생산 결과에서 검증해야 한다.

## PRISM 괄호 약어의 종목 오인: 별도 정합성 수정

합성 입력으로 `20일 이동평균(SMA20)`, `50일 이동평균(SMA50)`, `기준시각(UTC)`,
`낸드(NAND)`가 종목으로 추출되는 오류를 재현했다. 바로 앞의 명확한 설명 문구와
해당 약어가 함께 일치할 때만 제외하고, 회사명(심볼)·명시적 티커 목록·모호한
문맥은 보존한다. 같은 판정을 가격 블록의 시작·끝·한 줄 복수 종목 판단에도
적용해 설명 약어가 실제 회사의 가격 블록을 자르지 않도록 했다.

정규화 버전은 `prism-telegram/v3`이며, 회귀검사는 설명 문맥·회사명·티커 목록·
한국 6자리/클래스 심볼·여러 회사의 가격 분리·문서 excerpt를 포함한다. 이는
GOOGL·SHEL 분석 실패의 직접 원인으로 확인된 수정이 아니다. 기존 성과 DB의
과거 오인 행은 삭제·수정하지 않았다. 원문 근거에 따른 과거 행 격리와 모호한
심볼의 실제 상장종목 검증은 별도 작업이며, 새 파서만으로 해결됐다고 간주하지 않는다.
