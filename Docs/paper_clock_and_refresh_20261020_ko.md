# 내부 가상매매의 시계와 실행 원본 갱신

2026-10-20 KST 조사에서 PC 시계가 time.windows.com보다 약 1.2초 느렸고 Windows 시간 서비스가 중지돼 있었다. 일부 KIS 호가가 수신 시각보다 약 0.5초 미래로 보인 원인이다. 사용자가 Windows 시간 동기화를 완료한 뒤 측정 오차는 약 0.002초였으며 기존 코드의 호가 차단이 해제됐다. 시세·호가의 원래 시각이나 미래 데이터 허용 범위는 수정하지 않는다. 시간 동기화 버튼 실행 직후에도 서비스가 보정 중일 수 있으므로 실제 오차와 다음 가상매매 완료 기록을 확인한다.

기존 실행 원본은 정해진 장중 체크포인트(미국은 대체로 한 시간 간격)에서 생성되고 생산 작업 점검은 15분 간격이었다. 소비자는 실행 원본 10분, 개별 신호 120초를 검증하므로 체크포인트 사이에는 신규 주문을 막는 것이 맞았다.

기존 `LocalAutomation-run-due`의 점검 간격을 5분으로 맞춘다. 기존 가상매매 또는 KIS 모의 전략이 명시적으로 활성화돼 있고 정규장이 확인되면, 최근 원본이 120초 이상 지난 경우 새 실행 오버레이를 계산한다. 기존 전체 리서치 기준자료를 이용하되 시세·판단·주문 제안을 새로 계산하고 완료 후 기존 소비자에 전달한다. 원래 신호를 재발행하거나 유효기간을 연장하지 않는다. 선택적 LLM 재분석은 이 경로에서 실행하지 않는다.

같은 생산 작업 잠금과 Windows IgnoreNew 설정을 사용해 동시 생산을 막는다. 성공한 생산은 5분 예약 구간마다 최대 한 번 실행하며, 실패·진행 중 시도는 실제 경과 5분과 세션별 연속 실패 3회 제한을 유지한다. 09:05:05 성공 후 09:10:04 예약 실행처럼 시작 시각이 조금 빨라졌다는 이유로 다음 구간을 건너뛰지 않는다. 구간이 바뀌어도 최신 원본이 120초 미만이면 재생산하지 않는다. 주말·장외·확인되지 않은 세션에서는 실행하지 않는다. 원본이 신선해도 매매 가능한 판단과 명시적 주문 제안이 없으면 거래하지 않는다. 원본이 10분을 넘거나 개별 신호가 만료되면 기존 차단은 유지된다.

검증은 오래된·누락·미래·잘못된 시각, 정규장 여부, 기존 활성화 조건, 재실행 간격, 실패 제한, 미국 세션 날짜의 KST 자정 경계, 원본 파일 불변성과 기존 소비자 연결을 오프라인으로 확인한다. 운영에서는 연속 자동 생산 주기의 원본 나이·전달 시각·호가 차단·평가 완료를 비교한다. 다음 국내 정규장에서도 같은 측정을 수행하고 실제 유효 신호와 단순 관측 데이터의 전달을 구분해 보고한다. 실계좌 자동 주문은 비활성이다.
