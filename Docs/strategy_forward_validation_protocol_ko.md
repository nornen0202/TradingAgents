'왕복 표본'은 동일 시장·전략 버전·종목의 전략 소유 재고가 0→양수→0이 된 경제적 보유 episode다. 누적 체결 조회100회, 한 주문의 여러 부분 체결, 동일 자료의 반복 관측은 각각 독립 표본100개가 아니다. 양수 부분 체결과 비용은 보존하고, 미확정 취소·남은 수량·동일 거래일 상관을 표시한다. 거래 없음·휴장·실제 장애·결측을 서로 구분한다.

관측일 분모는 동결한 기간의 거래소 거래일 전체다. 정상 WAIT일은 유지한다. 장애일과 늦게 수집한 손실 거래를 삭제하지 않는다. 자료가 없어 NAV를 검증하지 못한 날은 '수익률0'으로 채우지 않고 미확인으로 남겨 평가를 차단한다. 휴장일은 거래일 분모에 넣지 않으며 DST는 거래소 현지 시간으로 해석한다.

## 5. 비용·정산·정정과 손익 범위

1. 실제 체결 가격에 이미 포함된 실현 가격 슬리피지를 actual_cost에 다시 더하지 않는다. 동시 호가와 실제 체결가의 차이는 별도 bps 진단으로 보존한다. 호가 시점·매수 ask/매도 bid·방향·단위가 미확인일 때 슬리피지도 null이다.
2. 매수·매도 양쪽 비용, 수수료·매도 관련 부과금·해당 세금·필요한 환전/자금비용·정산 범위를 주문/부분 체결에 귀속한다. 0원은 실제 증거가 확인한 명시적0 또는 해당 비용의 비적용 근거가 있을 때만 쓴다. 누락은0이 아니다.
3. 원래 broker/order/account scope·수량·대금·통화와 맞는 원문 증거를 append-only로 수용하고, 후속 정정은 앞선 사건을 참조해 이후 가용 시점부터 재평가한다. 과거 cutoff의 보고서를 후일 정정으로 조용히 바꾸지 않는다. 중복 import·누적 조회로 비용을 두 번 차감하지 않는다.
4. 모의 API가 비용·정산을 지원하지 않거나 지원이 입증되지 않았으면 `UNVERIFIED/UNSUPPORTED`를 구분한다. 실전 호스트 비용 API 우회, 계좌 일별 총비용의 임의 전략 배분, 실제 계좌 주문을 통한 비용 확보를 하지 않는다. 승인된 주문별 정산내역 import가 필요하면 원문·무결성·귀속·가용 시점 검증을 먼저 충족한다.
5. 10/30/50bp 비용 민감도는 **확인된 매수+매도 체결대금**에 적용하는 가정으로 유지한다. 실제 비용·net_pnl을 대신하지 않으며 미래 열린 보유분 청산 비용은 별도 가정으로 표시한다. 원래 reserve30bp와도 구분한다.
6. 사용자가 제공한 국내 편도0.147%, 미국 편도0.25%, 환전우대60%는 기존 연구의 입력이다. 이것만으로 모의 주문의 실제 청구 비용을 확정하지 않는다. 9월30일 문서의 세금·환전 스프레드는 당시의 연구 가정이며 오늘의 실제 정산률로 자동 적용하지 않는다.
7. 모델·데이터 비용은 금액 영수증·과금 기간·배분 규칙·통화/FX 시점을 별도로 보존한다. 토큰 수는 금액이 아니다. 실패·재시도·후처리 모델 호출도 같은 고정 배분 범위에 포함한다. 정액 구독은 검증된 총액의 사전 배분과 추가 사용에 따른 한계비용을 분리하며, 배분액을 증권사 실제 수수료라고 부르지 않는다. 공통 데이터 비용은 두 비교군에 같은 규칙으로, AI 추가 비용은 해당 군에 귀속한다. 운영비가 미확인인 경우 거래 순손익이 계산돼도 운영 순손익은 null이다.
8. 열린 보유분의 미실현 평가, 현금흐름, 실제 확정 비용을 포함한 NAV 경로와 청산 완료 거래의 실현 손익을 별도로 보인다. 관측 종료에 왕복 수를 맞추기 위한 강제 SELL을 만들지 않는다. 종료 시 미청산·미정산·미확정 정정은 미충족으로 남긴다.

## 7. 동일 조건 기준선과 기존 실험 registry의 한계

주 비교는 사전 고정한 기존 정상 전략 버전과의 관측 비교로 설계하고, 현금 유지와 동일 투자 가능 종목의 단순 규칙을 보조 기준으로 검토한다. 추가 매매를 생성하지 않는다. 비교군에도 같은 시장별 C0·입출금·종목 허용목록·정규 시간·거래 가능한 자료·정수1주·건당/일일/집중도 제한·동일 비용 정책·신호 가용 지연·거절/미체결 처리를 적용해야 한다. 기준선의 주문 불가능한 종목·분할 수량·미래 가격을 허용하면 공정 비교가 아니다.

정상 전략은 실제 KIS 모의 체결을 사용하되 비교군을 단순 next-open 체결로만 추정했다면 차이를 명시한다. 이 경우 '실제 체결 조건이 같은 전략 우위'는 미확인이다. 현금 유지의 이자는 실제 해당 모의 범위에서 확인된 것과 연구상0 가정을 구분한다. 원래 허용목록 밖의 지수 ETF를 실제 매수하지 않는다. 지수 가격은 가격 경로 참고 자료로만 표시하며 자본·현금·비용·위험이 다른 지수와의 단순 차이를 전략 alpha로 부르지 않는다.

기존 `ExperimentRegistry` 계약은 다음과 같다.

- spec 필드가 정확히 `id/hypothesis/universe/capital/currency/costs/benchmark/baseline_rules/ai_rules/training_end/forward_start/forward_end`여야 한다. `training_end < 등록 시각 < forward_start < forward_end`, 등록 후 시작 전 동결과 `spec_hash`를 요구한다.
- 같은 세션의 baseline/AI 목표를 개장 전에 함께 기록한다. `data_as_of <= recorded_at < open_at`, 데이터 버전·같은 완전 가격 패널·모델 비용·검증 시간을 보존한다. 앞선 미관측 세션을 버리고 나중의 좋은 날부터 기록할 수 없다. 정정 없이 UPDATE/DELETE하는 기능은 없다.
- 가격 모형은 현금 제약·long-only **분할 수량/next-open 가상 체결**이고 부분 체결·유동성·정산을 모사하지 않는다. spec의 편도 `fee_bps/slippage_bps`는 가정이며 실증 주문별 비용을 대신하지 않는다. 모델 비용은 평가 통화의 유한한 비음수 숫자를 요구한다.
- 따라서 이 registry를 읽는 카드는 연구용 미래 모의 비교 증거이며 정상 KIS 원장의 체결 수·실제 수익에 합산하지 않는다. 실제 KIS1주·현재 승인·정산에 완전히 부합한 비교라고 표시하지 않는다. 비용·모델 비용이 미확인일 때0을 넣어 등록하지 않는다. 이미 종료된 기간을 오늘 등록·동결해 미래 검증이라고 부르지 않는다.

이 초안은 registry를 열거나 생성하지 않았고, register/freeze/record_decision/record_session도 호출하지 않았다. 카드의 읽기 전용 빈 상태는 실험 미등록이라는 사실로 표시한다. 등록 여부와 관측 자료의 당시 가용 시점 검증은 별개다.

## 8. 중단·보류·실패 판정

기존 주문 시스템의 차단·위험 축소·중지 정책이 항상 우선한다. 평가 문서의 새 기준으로 주문 상태를 직접 바꾸지 않는다.

- 미래/불명 시점 데이터, 원본·승인·owner·정책 해시 불일치, 다른 전략/계좌 체결 혼입, UNKNOWN 제출/취소, 중복 체결·비용, 정정 계보 불일치가 있으면 해당 평가를 INVALID/UNVERIFIED로 보류하고 첫 원인·소유자·다음 증거를 기록한다. 주문 재전송이나 원장 수동 수정으로 숫자를 맞추지 않는다.
- 필수 데이터·수수료·정산·C0·FX·모델 비용이 누락된 성과는0으로 채우지 않는다. 소진한 원래 연구/시세 예산은 다음 원래 세션·허용된 정상 조건에서만 재판정한다.
- 실제 거래일이 지났으나 관측이 누락된 경우 MISSED/UNVERIFIED로 남긴다. 다음 성공으로 과거 실패를 지우지 않는다. 정상 WAIT일을 오류로 바꾸지 않고, 자료 실패를 정상 투자 WAIT로 숨기지 않는다.
- **미승인 평가 설계 제안:** 비교 가능한 비용 포함 전략 NAV를 검증할 수 있을 때 고정 C0 대비 최대낙폭5%에 도달하면 파일럿의 수익성 통과 판단을 보류하고 root/사용자 검토 대상으로 기록한다. 이것은 정상 전략의 손절·강제 청산·주문 허용 변경이 아니다. NAV/비용이 미확인이면5% 도달 여부도 미확인이다. 실제 주문 중단·청산은 기존 규칙과 별도 권한으로만 처리한다.
- 종료 시 최소 표본·기간 외 검증·정산·정정 범위를 충족하지 못하면 INCONCLUSIVE/NOT_READY다. 음수 성과 또는 양수성/비교 우위 근거 부족도 그대로 보고한다. 데이터 품질을 통과한 뒤의 손실은 시스템 결함으로 자동 분류하지 않는다.
- 별도 실투자 검토를 시작하려면 실제 비용 후 성과·기간 외 결과·손실/낙폭·장애 대사·관측 한계를 사용자에게 제출한다. 승인된 금액·계좌·기한·권한과 별도 실거래 중단/복구 계획이 없으면 real 주문은 계속 비활성이다. 모의 수익으로 실거래 수익을 보장하지 않는다.

## 9. 보고서·UI/UX 제시 형식

본문 첫 화면은 아래 네 블록으로 구성한다. 자료 전체를 숨기는 요약이나 기존 보고서 재작성 명령이 아니다. 다음 정상 보고서의 표시 형식 제안이며, structured coverage와 원래 결정·수치·PIT 검증을 그대로 보존한다.

### A. 바뀐 점 최대3개

각 항목을 `무엇이 바뀜 → 실제 증거·기준 시각 → 사용자에게 미치는 영향` 순서로 적는다. 새 변화가 없으면 없다고 표시한다. PR·테스트 수·새 snapshot 수를 체결·수익 증거로 대체하지 않는다. 판단·시세·체결·비용 중 무엇의 변화인지 명시한다.

### B. 지금 할 일 또는 기다릴 조건

시장별 한 카드에 현재 시장 세션, 정상 전략 BUY/SELL·왕복 표본, 거래 순손익/운영 순손익의 확인 범위, 첫 미충족 단계, 담당, 다음 실제 실행 조건을 먼저 보여준다. 실제 승인 행동이 없으면 '관망: 원래 승인 또는 정상 자료 대기'라고 적고 새 주문을 유도하지 않는다. 연구 자료 회복과 원래 투자 판단 WAIT를 따로 설명한다. 재시도 소진·완료 미확인·휴장·미결 대사·비용 미확인을 구별한다.

### C. 전체 종목 상세

원래 준비된 전체 허용·보유·관심 커버리지를 정확히 한 번씩 포함한다. 종목별 역할·원래 thesis·현재 엔진 행동·유효기간·원문 완료 시각·현재 시세 시각·자료 상태·가격 조건·무효화·위험 축소 근거·우선순위를 유지한다. 표의 결정 NONE/WAIT/조건부 행동을 요약 문구에서 즉시 BUY로 승격하지 않는다. 확신도·순위·원래 숫자·부분 실패도 숨기지 않는다. 첫 화면은 한국어 설명, 진단 코드·원문 receipt는 확장 상세로 제공한다.

### D. 감사 부록

분석/실행/관측/수집/확정/정산/정정 시각, source revision·run/계보·원문 hash, 커버리지 receipt, 실제 비용과 가정, 관측일·청산 episode·미결 수, 실패창·재시도 상태, 비교 설계·모델/데이터 비용·기간 외 결과·미충족 항목을 남긴다. 공개 화면에서는 계좌·인증·브로커 주문번호·사용자 경로를 노출하지 않고 권한 있는 비공개 증거로 연결한다.

기본 사용자 시각은 KST와 명시된 기준 시각이며 미국 카드에는 거래소 현지 NY 시각/세션 날짜를 함께 표시한다. 하루 전후나 DST가 바뀌어도 같은 사건을 중복 집계하지 않는다. 로딩·빈 자료·오류·마지막 성공 자료의 시각을 즉시 보여주고, 조회 timeout·중복 새로고침 방지·실패 후 재시도는 주문 권한과 분리한다.

향후 화면 확인은 실제 정본 자료로390px와1440px에서 '오늘 달라진 점', '정상 전략 체결 수', '왜 거래하지 않았는지', '다음 증거·담당'을 찾는 흐름을 검증한다. 오래된 자료를 보는 경우 그 사실을 첫 화면에 표시한다. 수익 값이 null인데0원처럼 보이거나 숨겨진 상세에서만 차단 원인을 찾게 되면 표시 검증 실패다. 이 초안에서는 화면 테스트를 실행하지 않았다.

## 10. 인계할 판정과 남은 승인

- **완료:** 기존 목표·정책·공식 벤치마크·평가/실험 계약을 대조한 이 문서 초안 작성.
- **실제 검증:** 정상 전략0이라는23:07:41 정본 읽기 감사, 기존 별도 왕복·보호·실패 증거와 코드 계약의 범위. 초안 자체로 새로운 체결·비용·통계를 관측하지 않음.
- **미검증:** 다음 정상 전체 연구·채택, 연속 장중 소비, 정상 BUY/SELL, 실제 비용·정산·정정, 반복 표본·운영 순손익·비교 우위·기간 외 결과·실거래 수익.
- **막힌 조건:** 현재 정상 행동/표본 없음, 비용 증거와 평가자본/비교·통계 설계의 사전 동결 미완료. 새 통계 숫자는 미승인 제안이다. 이 문서 작성으로 실험/주문/실투자 승인이 생기지 않음.
- **다음 담당:** root가 실제 배포·보호 검증 및 남은 자료 경로를 닫고, 기준 설계 검토와 원래 허용된 미래 실행 조건을 구체화한다. 보고 담당자는 기존 공식 prepare→publish→ACK→정확한 Pages 전달 절차를 사용한다. 기존 pending·ACK·원장을 보존하며 중복 발행하지 않는다.
