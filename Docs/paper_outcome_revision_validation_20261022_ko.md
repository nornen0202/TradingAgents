# 체결 성과 개정 및 회고 메모리 검증 — 2026-10-22

## 변경 범위

늦게 들어온 체결 증거로 FIFO 성과 배분이 달라질 때 원본을 보존하면서 결과를 개정하고, 당시 공개된 개정만 조회하도록 보강했다. 회고 메모리에서는 실제 이용 가능 시각과 수집 시각을 검색 전에 검증하여 미래 기록이 과거 검색 결과와 BM25·태그 점수에 영향을 주지 않도록 했다. 이 문서의 로컬 검증 결과는 해당 변경의 최종 CI·운영 배포 및 실제 체결 검증을 대신하지 않는다.

## FIFO 성과 배분 개정

매도 체결 하나의 전체 FIFO 배분을 `RETROSPECTIVE_ALLOCATION` 개정으로 추가한다. 개정에는 이전 개정 ID, 입력 증거의 기준 시각과 ID 목록, 회고 구성원 ID 목록, 내용 해시가 포함된다. 동일한 매수·매도 쌍이라도 배분 수량이 바뀌면 새 개정에 속하는 새 회고를 추가한다. 기존 체결·회고·학습 기록은 수정하거나 삭제하지 않는다.

- 발생·공개·확인·정산·수집의 5개 시각이 기준 시각까지 검증된 증거만 선택한다. 해당 시점에 공개된 단일 개정 체인의 최신 개정만 경제적 성과로 집계하며, 미래 개정이 과거 개정을 숨기지 못하게 한다.
- 원가를 알 수 없는 초기 보유분이 뒤늦게 확인되면 빈 배분 개정으로 기존의 원가 확인 가능 성과를 철회할 수 있다. 기존 행을 삭제하는 방식은 쓰지 않는다. 개정 이전 형식의 회고는 첫 개정이 공개되기 전까지만 활성 근거가 된다.
- 매수·매도 양쪽의 수량 한도, 양쪽 비용의 수량 비례 배분, 순손익 계산, 모드·통화·종목·체결 연결을 검증한다. 분기된 개정 체인, 누락된 구성원, 내용 해시 불일치, 동일 매수 수량의 중복 배분은 차단한다.
- `evaluated_at`은 입력 증거의 상한이다. 개정의 공개·수집 시각은 기본적으로 실제 UTC 현재를 사용하여 과거 계산 결과를 당시 이미 알려졌던 것처럼 소급 노출하지 않는다. 명시적인 실행 시계가 있는 생산자와 오프라인 fixture만 그 시계를 주입한다.
- 회고·학습·개정은 하나의 SQLite savepoint로 저장한다. 실패하면 전체를 되돌리고, 같은 결과의 재발행은 행을 추가하지 않는다. 늦게 수집한 초기 잔고는 전체 계좌 재생에서 초기 상태로 적용하며, 종목별 조회에서는 의존성 검증에만 사용하고 다른 보유분을 노출하지 않는다.
- 여러 매도의 일부만 갱신한 경우에는 서로 겹치는 과거 입력 증거가 일치하는지 검사한다. 수량 중복이 없더라도 다른 계산 근거가 섞인 성과는 차단한다. 기존 형식과 새 개정의 부분 전환도 차단하며 paper·demo·actual 생산자는 관련 매도를 같은 발행 시각으로 재계산한다.
- 초기 잔고는 모드·통화별 하나만 허용하고 첫 체결보다 늦게 발생한 잔고는 거부한다. 종목별 조회도 필요한 타종목 체결·주문 의존성의 시점을 검증하여 같은 보호 규칙을 적용하며 그 자료를 출력에는 노출하지 않는다.

재생과 성과 요약은 같은 개정 선택기를 사용한다. `closed_trades`는 **활성 회고 구성원 수**이며 매도 체결 수나 계좌 왕복 횟수가 아니다. 하나의 매도가 두 매수 lot에 배분되면 두 건이다. `learned_intuitions`는 활성 회고에 연결된 유효 학습 행 수이며 회고 수와 항상 같다는 계약은 없다. 이 개정 처리만으로 실제 수수료·정산 또는 실투자 적합성이 확인되는 것은 아니다.

성과 요약의 `analysis_as_of`는 이 체결·회고 근거 선택에 적용된다. 기존 추천별 가상 성과 집계는 전체 기록 범위를 유지하므로, 요약 전체를 동일 시점으로 제한된 과거 실거래 성과라고 해석하면 안 된다.

예를 들어 같은 수량의 매수 원가가 100인 체결만 보이던 시점에는 매도가 120이고 양쪽 합계 비용이 2일 때 순손익이 18이다. 나중에 발생 시각이 더 빠른 원가 90의 매수가 확인되면 새 개정의 FIFO 순손익은 28이 된다. 과거 조회에는 여전히 당시의 18이 보인다. 이 숫자는 오프라인 fixture이며 운영 계좌의 성과가 아니다.

## 조회 시각 계약

- 시간대가 있는 timestamp 조회는 해당 순간을 포함하는 정확한 상한이다. `outcome_known_at`, `available_at`, `ingested_at` 및 제공된 정산 시각이 모두 시간대가 있는 값이어야 한다. 미래·누락·잘못된 필수 시각과 모순된 시각 순서는 검색 근거에서 제외한다.
- `YYYY-MM-DD` 조회는 해당 **UTC 날짜 전체**를 포함하고 다음 날 UTC 자정은 제외한다. 이 경로는 과거의 성과·정산 날짜 표기를 허용하지만 `available_at`과 `ingested_at`에는 실제의 시간대 포함 시각이 필요하다. 날짜 조회를 현재 연구의 정확한 실행 시각으로 해석하면 안 된다. 실행 순간의 검증에는 timestamp를 전달해야 한다.
- 두 조회 경로 모두 조회 시 한 번 읽은 **실제 UTC 현재 시각**을 추가 상한으로 적용한다. 현재 또는 미래 날짜를 전달해도 실제 현재보다 늦은 근거는 한도 적용과 점수 계산 전에 제외한다. 실제 현재와 같은 시각은 포함하되, 과거 날짜의 다음 자정 제외 경계는 유지한다. 이 상한은 검색에만 적용하며 회고의 원래 의사결정일 검증 의미를 바꾸지 않는다.
- `as_of`와 메모리 객체의 기본 `as_of`가 모두 없으면 기존의 시각 제한 없는 진단 검색을 유지한다. 이를 과거 시점 투자 판단의 검증 근거로 사용할 수 없다.
- 이용 가능 시각 또는 수집 시각이 없는 기존 기록은 시점 제한 검색에서 제외한다. 운영 DB 자동 마이그레이션, 기존 행 수정, 과거 시각의 추정 주입은 하지 않는다.

## 원본 보관과 검색 점수

추가·재로드·조회 경로에서 원본 기록을 자동 삭제하거나 변경하지 않는다. SQLite의 원본 전체를 유지하고, 시각 및 메타데이터 조건으로 적격 기록을 고른 뒤 `memory_max_entries`를 조회 활성 기록 수에 적용한다. BM25 색인과 태그 점수는 이 적격 집합만으로 계산한다. 입력 및 반환 메타데이터는 복사하여 호출자의 변경으로 원본이 변하지 않도록 한다. 명시적인 기존 `clear()` API의 계약은 변경하지 않았다.

## 회고 생성 및 과거 시뮬레이션 영향

회고 생성은 성과·정산 시점의 유효성을 모델 호출 전에 검사한다. 모델 응답이 완료된 뒤의 실제 UTC 시각을 `available_at`과 `ingested_at`으로 기록한다. 과거 상태에 포함된 이용 가능 시각으로 새로 생성한 회고를 소급 등록하지 않는다. 기존 LLM 주입과 정형 의사결정 파싱 경로를 유지한다.

따라서 현재 실제로 생성한 회고를 walk-forward의 과거 시뮬레이션 시점에서 자동 재사용하지 않는다. 시뮬레이션 시각에 학습된 것으로 간주하려면 별도의 명시적 정책과 검증이 필요하며, 이번 변경은 그 정책을 추가하지 않는다. 비용 평가 결과를 메모리에 자동 입력하는 연결도 추가하지 않는다.

## 미충족 기준과 적용 한계

- 국내·미국 정상 전략의 증권사 모의 체결은 현재 각각 **0건**이며 국내 검증 왕복 체결도 미완료다. 코드·fixture 통과를 실제 체결 완료로 간주하지 않는다.
- 실제 수수료와 정산 상태는 확인되지 않았다. 비용 명세 수입, 실제 비용의 출처 확인, KIS 실제 비용 연결, 체결 자체의 정정 모델은 이번 FIFO 개정 범위 밖이다. 실제 비용을 포함한 성과와 정산을 증명하기 전에는 실투자 적용 가능성을 확정할 수 없다.
- 데이터 회복 후 새 정상 연구의 완료, 원본 승인과 주문의 연결, 실제 모의 BUY·SELL 증거, 왕복 수량·비용·정산 정합성, 비용 포함 성과 및 잔여 위험을 순서대로 확인해야 한다.
- 원래 연구 승인, 계좌 소유권·잠금·원장·한도·시점 검증을 보존한다. 실계좌 주문 비활성 및 실제 투자로 자동 전환하지 않는 원칙을 유지한다. FIFO 비용 결과를 금융 회고 메모리에 자동 연결하는 동작도 추가하지 않았다.
