# 2026-09-28 공개 입력 및 ChatGPT 재분석 신선도 감사

## 확인된 문제

- 사용자 제공 공유 대화와 국내 분석 대화가 9월 15일 계좌·원분석을 참고값으로 반복 사용했다. 9월 28일 답변은 현재 계좌 0/13 확인 상태에서도 과거 수량을 바탕으로 상세 전략을 전개했다.
- 조사 시점 GitHub Pages는 실제로 갱신돼 있었다. 국내 producer는 9월 28일 13:56, 원분석 완료는 07:21, 계좌 관측은 13:56이었다. 웹 조회 도구에서는 Pages 접근 실패, 일반 HTTP에서는 200이었다. 이는 관측된 클라이언트별 접근 차이이며, OpenAI 내부 오류 원인까지 확정한 것은 아니다.
- 문서 게시 시각, overlay 실행, 원분석 완료, 마지막 완료 일봉 거래일, 시세·계좌 관측시각은 다른 개념이다. 휴장·주말 때문에 마지막 완료 일봉이 이전 날짜인 것과 생산 중단을 혼동하면 안 된다.
- 원분석 거래일을 분석 원본이 아닌 overlay ticker에서 가져오는 코드가 남아 있었다.
- 공개 계좌 선택이 계좌 관측시각 대신 manifest 나열 순서에 의존했고, 누락 현금·총자산을 0으로 변환했다.
- 위험 대응으로 매도 표시된 행에 이전 매수 돌파·RVOL 조건이 실행 조건으로 노출되는 사례가 있었다.

## 적용한 통제

1. 공개 AI 입력: `ai/kr/latest.md`, `ai/us/latest.md`. 이미 공개된 계좌·전략에서 필드를 명시적으로 선별한다. 계좌번호·주문·원시 응답은 복사하지 않으며 공개 계좌에서 승인되지 않은 보유 종목은 경량 독자에 포함하지 않는다.
2. 별도 공개 호스트: `raw.githubusercontent.com/nornen0202/TradingAgents/public-context/{kr,us}/latest.md`. 기존 공개 정보의 경량 사본만 게시한다. 계좌 정보가 공개되는 범위는 기존 승인 범위와 같지만 사본은 Git 이력에도 남는다는 특성이 있다.
3. 미러는 Pages manifest와 파일 SHA-256·크기·생성시각·정확한 경로 집합을 검증하고 원자적 Git ref 갱신으로 공개한다. 이전 게시로의 역행·미래 시각·혼합 배포·임의 파일 추가를 거부한다. 인증·안전 제한 우회 수단이 아니다.
4. 국내·미국 v5 프롬프트: 경량 원문과 대체 경로, 실제 원문 시각의 직접 인용, 현재 계좌 미확인 시 과거 계좌의 개인화 재사용 금지, 미실현 수익률과 최대낙폭 분리, 매도/매수 조건 분리, 가상 추가자금 5개안 유지.
5. 공개 계좌는 유효 health와 시간대가 있는 과거 관측 중 가장 최신을 선택한다. 현금·총자산의 null은 0과 구분한다. 원분석 거래일은 계보로 해결된 원본에서 가져온다.
6. 새 전략 번들과 기존 모바일 전략의 위험 대응 조건에서 매수 돌파·거래량 조건을 분리한다. 주문 생성·체결은 수행하지 않는다.

## 검증 원칙 및 운영상 한계

- 단위·회귀 테스트에는 잘못된 시각, 계좌 순서 역전, 누락 현금, 계좌 식별자 제외, 사본 무결성·역행 방지, 매도 조건, 양 시장 프롬프트가 포함된다.
- 전체 테스트, 정적 검사, 모바일 레이아웃·상호작용 검증 후 PR을 병합한다. 배포 후 원본/사본 해시와 ChatGPT 실제 조회를 별도로 확인한다. 프롬프트 저장 성공만으로 분석 품질 검증 완료라고 주장하지 않는다.
- 클라우드 예약은 기존 국내 월~금 13:00, 미국 월~금 23:30, Asia/Seoul을 보존하고 prompt만 갱신한다. 이 수정은 예약 모델 선택 가능 여부를 바꾸지 않는다.
- 공개 웹 접근·캐시·예약 실행 지연 등 외부 서비스의 모든 미래 실패를 보장할 수 없다. 자료를 못 읽으면 미확인으로 남기는 것이 올바른 실패 처리다. 오래된 입력을 사본 발행만으로 최신화하지 않는다.
